# Native and workspace contracts

This document describes the private bridge implemented by `native/Sources/SmipBridge/`, its TypeScript schemas in `src/contracts/`, its client in `src/native/bridge-client.ts`, and the workspace/exploration APIs. Native directory capabilities authorize physical access. Workspace services apply exclusions and generation policy before requesting that access.

## Process and framing

Launch `SmipBridge <generation>` with an explicit environment. The client creates a fresh generation for each process and serializes requests. Each request is a closed object containing `wireVersion: 1`, a nonempty `requestId`, `generation`, and a discriminated `operation`. The TypeBox schemas and Swift parser reject unknown fields and malformed values. Base64 must round-trip to its canonical encoding. Only byte `0x0A` separates records; Unicode line separators remain data inside JSON strings.

Responses repeat the envelope identities. A request produces zero or more `bytes` or `entry` records followed by exactly one `terminal` record. Bytes use base64. A source response becomes usable only when its terminal receipt agrees with the accumulated byte count and SHA-256. A directory receipt covers the entry count and SHA-256 of the concatenated UTF-8 sequences `entryKind + NUL + name + NUL`, in emitted order. Directory entries are sorted by their raw UTF-8 names.

Malformed UTF-8, invalid frames, unknown versions, mismatched identities, duplicate terminals, unexpected record kinds, inconsistent receipts, and premature process closure fail the request and retire the client. Retirement rejects queued operations, invalidates handles, and joins process closure. A normal source failure returns a `failure` result and leaves the process available. `NativeFailure` exposes its code and optional errno. `NativeWorkerFailure` exposes the exit/signal/spawn receipt and the affected source identity when one was supplied.

## Operations

- `queryStructure` applies RPCE's graph traversal, output budgets, signature admission and reply formatting to an immutable root-local snapshot. It returns both the typed reply and rendered text. Headless root/file identities are stable SHA-256-derived UUIDs, used for the reference's ordering and equality checks.
- `renderFileTree` renders captured root/entry/selection data through RPCE's snapshot renderer. It supports full, folders, selected and automatic views, a scoped start directory, folder depth limits and legends. `onlyIncludeRootsWithSelectedFiles` controls selected-root filtering; full mode with an empty selection retains all roots. `showCodeMapMarkers` controls the plus markers and their legend. Callers supply each file's marker state for the presentation they are rendering. Exploration uses retained ready structure. The native adapter constructs temporary snapshot identities; these identities do not appear in the output or grant filesystem access. Relative displays use declared root aliases.
- `renderPromptAssembly` combines formatted section snippets through RPCE's `PromptAssemblyBuilder`. The caller supplies section order, disabled sections and the user-instruction duplication setting. Null and empty snippets are omitted; repeated sections in the order are emitted repeatedly. User instructions duplicated at the top are included even when their ordinary section is disabled. A nonempty snippet gets a terminating newline if it lacks one.
- `renderClipboard` packages captured file entries, codemap presentation, meta instructions, a tree, Git text and literal user instructions through RPCE's clipboard functions. Entries identify ordinary files or authorized Git artifacts; authorization and acquisition occur before this boundary. Readable selected Git bodies take precedence over supplied Git text, including source slice handling. Codemaps and the optional tree form `file_map`; ordinary file blocks form `file_contents`. Caller flags control files, meta prompts, user instructions, dates, ordering, disabled sections, duplication and optional titles. File-block text uses the retained native formatter and slice assembler.
- `projectGitArtifacts` projects a captured snapshot manifest, present-file paths and optional MAP bytes through RPCE's Git artifact policy. The caller supplies comparison display, mode, inline settings, automatic-selection aliases, worktree metadata and warning. The result contains the original reply fields, primary and advertised aliases, and ordered artifact records. Primary automatic-selection membership follows MAP then all-patch order; per-file jump indexes retain gaps and alias collisions. Inline `brief` selects snapshot metadata and the changed-file tree; other inline modes use the full MAP. Missing or invalid UTF-8 MAP bytes omit the inline object. Snapshot identity and unsafe artifact paths return `gitArtifactProjectionError` with the source diagnostic. Projection performs no filesystem access and grants no selection authority; callers must acquire its inputs through admitted capabilities.
- `decorateGitArtifacts` decorates captured per-repository artifact replies with primary aliases and readiness warnings, then aggregates successful diff totals while counting every repository result. Warnings are trimmed and joined in acquisition-then-readiness order. Repository acquisition errors remain separate results.
- `describe` returns the thirteen supported extensions, automatic source-decoder identifier, canonical bytes for each pipeline, parse limits, and regex configuration. `jitCapability` records compiled engine support; `jitExecution` records whether matching at startup used compiled JIT, was disabled, or found JIT unavailable under the automatic policy.
- `openRoots` admits existing absolute directories, resolving an explicitly declared root alias and returning its declared/canonical paths, device/inode, access kind, and generation-bound handle. Source and output capabilities have distinct access kinds. An optional expected identity supports reopening the same authority in another process; disagreement fails with `rootChanged`. Duplicate names or canonical paths in one declaration fail. Reopening an identity that the process already admitted with the same access kind returns that admitted capability after the fresh path and identity checks; it retains no additional descriptor, and a source capability is never returned for an output declaration or the reverse.
- `listDirectory` accepts a source handle and either `{ kind: "root" }` or `{ kind: "descendant", path }`. It emits each entry as file, directory, symlink, or other, then a complete receipt. Directory fingerprints must agree before and after enumeration.
- `readSource` accepts a source handle, relative path, and an expected raw identity or null. It emits exact bytes and returns their identity, the unchanged descriptor fingerprint, and the eligible canonical artifact key or null for an unsupported extension. Missing paths, denied access, special files, symlinks, and changed observations have distinct failures.
- `extract` accepts an extension, exact base64 bytes, and the expected raw identity. It verifies that identity before decoding. It returns a retained core outcome, its canonical key, and, for ready artifacts, the original Swift API description and sorted defined type names. Unsupported extensions produce `unsupportedExtension` at the bridge level; they are not empty artifacts.
- `beginExport` creates one fresh, private run directory beneath an output handle and returns a run capability. `writeExport` exclusively writes `context.md` or `handoff.md`; `readExport` reads either file completely and returns its identity. `publishManifest` exclusively writes `manifest.json`, syncs the file and directories, and returns the written identity. The application finalizer owns material verification and the publication claim. A failure after manifest creation that leaves durability uncertain is `publicationUncertain`.

## File authority

Relative paths preserve filename spelling and Unicode. They reject absolute values, NUL, empty components, `.` and `..`. Root names are case-sensitive ASCII identifiers beginning with a letter and continuing with letters, digits, `_`, or `-`.

Directory traversal uses descriptor-relative opens with no-follow semantics. A fresh directory description avoids sharing enumeration offsets or filesystem caches between operations. Leaf reads use no-follow and nonblocking flags, then require a regular file through `fstat` before reading. Root aliases and directory identities are rechecked; export operations also recheck the run directory's identity. No descendant symlink is followed, and a source handle cannot authorize writes.

The source fingerprint records device, inode, size, POSIX mode, and modification/change times obtained from the opened descriptor. Device, inode, and timestamp seconds are decimal strings; nanoseconds, byte size, and mode are integers. Device identifiers retain the platform's signed representation. The bridge compares every field around acquisition and independently hashes the acquired bytes. Consumers use the captured mode for comparisons involving executable permissions. This establishes an observed byte sequence, not a filesystem transaction or future freshness guarantee. Application finalizers must reopen and check delivered material through the same authority.

## Decoding and extraction identity

`smip-strict-utf8-v1` accepts exactly the UTF-8 byte sequences that survive decoding and re-encoding unchanged. It preserves a leading BOM as U+FEFF, newline bytes, Unicode spelling, and empty input. Invalid sequences return `decodeFailed`; repaired text is rejected. Tree-sitter's internal UTF-16 offsets are distinct from raw UTF-8 byte identities.

The existing outcomes remain `ready`, `readyNoSymbols`, `oversize`, `decodeFailed`, and `parseFailed`. Oversize reasons distinguish UTF-8 bytes, UTF-16 units, and lines. Grammar/query exceptions are operation failures, and a crash is a worker failure.

Swift constructs the sole canonical artifact key. Pipeline domain `codemap-pipeline-identity-v2` includes the required regex-engine fingerprint along with the retained decoder, grammar/query, version, flag, and limit fields. The fingerprint hashes sorted-key JSON under `smip-regex-engine-v1`, including the pinned PCRE2/SLJIT source identities, patch set, Unicode version, width, recipe settings, and resolved JIT policy/support/execution facts. Platform, compiler, and hashes of library artifacts are separate build evidence. The client validates the canonical bytes' digest rather than reimplementing their encoding.

## Ownership and cancellation

`ProcessSupervisor` owns each child from spawn through the `close` event. Callers provide executable, argument array, working directory, environment, and the supervisor's `terminationGraceMs`. It sends SIGTERM on stop, escalates to SIGKILL after that grace, and awaits closure of the process and its streams. Its JSON diagnostics contain opaque process identities and exit/signal facts, not command arguments or stderr bodies.

Each `BridgeClient` owns one serialized native child. Aborting a request retires that client and rejects its queued work; closing one client leaves other clients under the supervisor running. Shared indexing must have its own owner: cancellation of a waiter releases its interest rather than aborting another owner's bridge. Supervisor closure stops admission and joins every owned child. A failed operation is never automatically replayed.

## Workspace generations and exploration

`SmipRuntime.declare(spec, signal)` admits named source roots and the output-root identity before warming. `WorkspaceSpec` requires ordered roots, explicit prefix/glob exclusions, and an absolute existing output directory. Names and canonical root paths are unique. The declaration key includes source/output identities, exclusions, state-directory exclusions, configured ignore settings, and the ignore implementation version. Each generation's policy identity records repository authority, effective settings and captured control files.

Every permitted directory is listed through the bridge. The native ignore reader accepts an admitted source-root capability and the fixed control names `.gitignore`, `.repo_ignore` and `.cursorignore`. For Git roots it resolves the containing repository, Git directory and common directory, then captures controls from the repository root through the loaded subroot. Policy inputs contain absolute logical paths and exact text/raw identity, explicit absence, or a diagnostic for an unavailable optional nested control. Mandatory Git controls require strict UTF-8, regular files, no leaf symlink and at most 4 MiB. Secondary controls use resolved metadata paths; protected paths remain denied. Invalid required controls prevent complete enumeration.

Parent rules precede descendant rules. The original hierarchical evaluator locks ignored prefixes to their controlling rules and acquires deeper controls only when its evaluation requests them. Ordinary directory crawling follows the original negation traversal hints. Explicit exclusions apply through every containing canonical root. Absolute denies match canonical source paths and equivalent paths through every containing admitted root's declared alias. Configured protected paths retain their declared spellings and include their existing canonical targets, including independently declared aliases. An absent optional credential file is denied at its declared path and at the physical path formed from its canonical existing ancestor plus the absent plain-name remainder, so creating it later beneath an independently symlinked parent cannot admit it. A dangling symlink or a remainder containing `.` or `..` components fails admission with `credentialPathUnresolvable`; current verification applies the same rule. No descendant source symlink is followed.

`refresh(signal)` registers its barrier before waiting and returns the immutable publication satisfying that barrier. One owner serializes scans and coalesces later requests into a follow-up scan. A later scan's failure affects only observers still waiting for publication. Every scan rehashes permitted regular files. The immutable snapshot separates enumeration completeness, settled processing, per-file structural outcomes/acquisition failures, and skipped-entry reasons. `inventoryDigest` describes content and policy; `generation` orders observations within the owner. An incomplete enumeration cannot admit an exploration operation. After native generation retirement, a later explicit refresh joins that generation's closure and reopens source and output roots against their original declared/canonical paths and device/inode identities. Failed requests remain failed.

Workspace handles and operations hold separate leases. Closing a handle prevents further calls through that handle and releases its lease. It does not revoke another handle or an already admitted operation. Shared extraction retains its producing owner until the extraction settles. A consumer's cancellation releases its observation of another owner's extraction. Cancelling a refresh observer releases that observer without aborting the shared scan. Runtime shutdown aborts inventory owners before joining clients, then joins native work, pending admission and operation lanes.

`openOperation(signal)` pins the current inventory and policy, including incomplete enumeration. Known-source exploration remains available; structural replies identify incomplete coverage. Draft admission requires complete enumeration and returns `enumerationIncomplete` otherwise. The first native tree/structure query or physical read lazily opens an operation-owned bridge against the originally admitted root identities. Operation closure aborts its physical work and waits for all admitted calls and owned child closure. Selected-tree requests consume a caller-supplied immutable `{ draftId, revision, sources }` projection; the draft owner is responsible for supplying authorized selection data.

### Persistent artifacts

Artifacts reside at `v1/artifacts/<shard>/<keyDigest>.json`. The closed record schema contains `schemaVersion: 1`, Swift-produced `keyCanonicalBase64`, `keyDigest`, `outcome`, `projection` only for ready outcomes, and `recordSHA256`. The checksum covers recursively key-sorted JSON of every other field. Array order is retained. Reuse validates the schema, canonical base64/key hash, correspondence to the current Swift key, checksum, and projection/outcome agreement.

Insertion writes and syncs a private exclusive temporary file, publishes by a no-clobber hard link, validates agreement with the published record, and syncs the directory. Existing corruption/conflict identifies the key and requires explicit invalidation. Pending extraction is deduplicated by key only after each caller has independently acquired authorized bytes. Schema-version-2 inventory observations capture structural disposition for failed acquisitions and use an exclusive temporary file and atomic rename. Workspace cache keys include the inventory schema version. Across processes, the last complete observation may win; it does not replace live authority. Restart checks persisted record integrity and reconciles current source before use.

### Lines, trees, and structure

Source acquisition tries UTF-8 first, then RPCE's retained character-encoding detector. macOS uses Foundation's heuristic when the detector cannot identify an encoding. Linux converts detector-selected encodings with its native codec and returns `decodeFailed` when detection or conversion fails. Some short Big5 and GB18030 files accepted by the macOS heuristic are undecodable on Linux. Lines are one-based; CRLF, lone CR, and LF terminate a line, and a trailing terminator adds no phantom line. Empty content has zero lines. `start_line` is one-based and defaults to 1. A positive start with `limit` reads at most that many lines; omitted or negative limits read the remainder, and zero returns no lines. A negative start reads the last N lines and rejects any supplied limit. Zero start is an error; starts beyond EOF return empty content and the source diagnostic. `offset` is the current start alias. Numeric strings use RPCE argument priority: integer start, integer offset, string start, then string offset. Returned content retains original terminators. Line records include byte offsets and lengths in the decoded UTF-8 representation. Continuation never splits a source line.

Tree requests use `type: roots` or `type: files`. File modes are auto, full, folders and selected, with optional root/directory scope and folder depth. The native RPCE renderer supplies tree text; stars identify selected implementation and pluses identify available code maps. Skipped entries are omitted. Response pages retain complete rendered lines, with the inventory digest and a continuation.

Structure queries use the retained RPCE seed-resolution, traversal, policy, DTO assembly and text formatter. Omitted seeds use the captured authorized full/sliced selection. Explicit input accepts 1–256 root-qualified file/directory selectors; a directory reference can identify a whole root. Direct files are resolved before explicit directories. Folder expansion visits captured child files before child folders, deduplicates physical paths and retains the first limit-exceeding file after 8192 unique candidates. The resulting seed metadata and graph truncation remain separate. Missing inputs are skipped; a request with no resolved files returns the source `path_not_found` reply. Names preserve case, normalize to NFC and match within one root. Breadth-first `uses`, `used_by` and `both` expansion accepts depths 1–4. Edges retain source-to-definition orientation even during reverse traversal; cycles, self-edges and each source's unresolved references remain in structured evidence. Names with more than 4096 definition candidates produce `too_common` instead of edges.

`size` selects small (40 nodes, 4000 edges, 32000 graph bytes), medium (120 nodes, 10000 edges, 96000 graph bytes) or large (200 nodes, 10000 edges, 400000 graph bytes). Roots share the remaining budgets in UUID order. Traversal checks the source's 10000ms per-root deadline. With `signatures: true`, whole signature texts share 1500, 4500 or 18750 estimated units respectively; oversized signatures are omitted with a diagnostic while later smaller texts can fit. `summary.tokens` charges admitted signature text and separators.

A ready-no-symbols artifact contributes a covered node with no definitions. Unsupported extensions have no graph slot and produce not-indexed seeds. Failed acquisition of a supported admitted file produces a pending seed; decode/parse failures and oversize artifacts produce terminal, not-indexed seeds. A supported candidate that becomes non-regular is terminal-excluded. Supported and classified counts include terminal-excluded candidates; pending candidates count only as supported. Incomplete enumeration remains indexing and unresolved names become `not_indexed_yet`. Graph and signature limits produce partial replies with source diagnostics. Structured output retains evidence that the source's text formatter omits, including unresolved records and self-edges.

The complete encoded reply, including native text and structured data, must fit `maxOutputBytes`; otherwise the result is `outputBudgetTooSmall` with its required size. Structure replies have no continuation.

### Read-only Git

`git` accepts `op: status`, `op: log`, `op: show`, `op: blame` or `op: diff` with a declared root name. Status returns branch/upstream and ahead/behind metadata when present, sorted staged/modified/untracked path sets, and a summary from one coherent porcelain-v2 observation. Status paths are relative to the owning checkout, including when the declared root is a subdirectory. Log defaults to ten commits and no path restriction; `path` is relative to the declared root. Blame requires a file path and accepts `lines` in `start-end` form. A valid ordered pair restricts the range; absent, malformed or reversed text selects the whole file, matching RPCE's argument handling. Log replies retain commit IDs, authors, ISO dates, subjects and file/insertion/deletion totals. Blame replies retain line numbers, abbreviated IDs, authors, ISO dates and content.

`show` requires a nonempty `ref`, resolves it to a commit and returns its full message and file/insertion/deletion totals. `detail` defaults to `"summary"`; `"files"` includes file statistics, and `"full"` includes complete hunks. `"patches"` maps to `"full"`, and detail matching is case-insensitive. `contextLines` defaults to three and `detectRenames` to false. Show uses Git's `<commit>^!` diff semantics. For a root commit, that expression compares the commit with captured live worktree bytes. Show and diff apply host denies to both rename/copy endpoints before acquiring returned bodies. Omitted paths are listed in `exclusions`; totals describe permitted evidence. Missing binary counts and empty hunk lists are omitted from the result. Invalid metadata returns `gitShowMalformed` with the source diagnostic before any diff command runs.

`diff` defaults to `compare: "uncommitted"` and `detail: "summary"`. Comparisons include `uncommitted:<base>`, `staged`, `staged:<base>`, `unstaged`, `mergebase:<base>`, `uncommitted-mergebase:<base>`, `staged-mergebase:<base>`, `back:N` and Git revision specifications. `main` and `trunk`, including staged/uncommitted prefixes, resolve the repository's main reference with merge-base semantics. Detail can be summary, files, patches or full; exactly one collected path upgrades summary to patches. Patches use RPCE's 300-line allowance; full retains complete hunks. `contextLines` defaults to three and `detectRenames` to false. Worktree and unstaged comparisons include untracked files; staged and revision comparisons exclude them. Results retain source totals, status counts, paths and hunk fields.

Diff `path` and `paths` are collected in that order. Relative inputs are checkout-relative Git pathspecs, including glob/magic/exclusion syntax. Absolute inputs under the checkout are literal paths. An explicitly scoped request whose paths normalize to an empty set produces an empty diff. A declared subroot admits read-only evidence from its owning checkout. Optional `worktree` names an advertised checkout of the same repository. Access requires loaded-root admission and matching checkout/shared-Git-directory identities, checked again before replying. Credential paths and explicit workspace exclusions remain denied. Both rename/copy endpoints must be permitted; omitted endpoints appear in `exclusions`. Ordinary workspace reads and selections remain scoped to declared roots.

`compare: "last"` reads the owning checkout's repo-scoped `CURRENT` and manifest, then compares the live worktree against the saved fingerprint's HEAD. A normalized named snapshot uses the same rule and takes precedence over a Git ref of the same name. `main` and `trunk` resolve the main reference before checking for a named snapshot. A missing date/minute-shaped snapshot ID produces `gitSnapshotNotFound`; a custom name with no readable manifest is parsed as an ordinary comparison. Missing CURRENT and unreadable CURRENT manifests return `gitSnapshotUnavailable` and `gitSnapshotManifestUnavailable` with RPCE's diagnostic text. These comparisons acquire fresh permitted diff bodies from Git; the saved manifest supplies the base HEAD.

During discovery, a scout can omit `root` from a diff request when its initial full-file or sliced selection elects a Git checkout. Each selected file resolves to its nearest checkout, including nested repositories. The checkout group requires one most-specific declared root containing all its selected files. Targets sort by root name, checkout key, repository ID and worktree ID; the primary target is the first sorted checkout containing the first selected full-file path, or the first slice path when no full files are selected. Election is deferred when the initial selection is empty or contains only codemaps. Mixed Git/non-Git ownership or ambiguous roots refuse implicit reads with `gitTargetRequired`. Standalone workspace Git calls require an explicit root.

Before each implicit diff, discovery revalidates every initially elected checkout, including checkouts removed from the current selection. Repository IDs identify the shared Git directory; linked worktree IDs also identify their per-worktree Git directory. A changed checkout layout or identity returns `gitRepositoryChanged`. Explicit root-scoped reads remain available when initial election is deferred or unavailable.

Draft-owned publication capture requires an initially available target. It re-elects the current ordinary full/sliced selection, requires a nonempty checkout set within the original identities, and revalidates both sets. A changed checkout set or empty current selection returns `gitSelectionOwnershipChanged`; an explicit requested checkout outside the frozen target returns `gitPublicationTargetDenied`. Draft revision and freeze generation are checked after authorization and after acquisition. Files may be added within an elected checkout; admission constrains ownership rather than the original filenames.

`DraftRuntime.publishGitSnapshot` writes an admitted captured comparison through the owner of mutations to its output directory. It resolves a snapshot ID before fetching a commit graph with at most 20 entries. It preserves quick/standard/deep snapshot bodies, records the creating draft UUID, writes CURRENT and runs count retention. Artifact projection uses confined reads of the saved MAP and optional artifact paths. After catalog registration and ownership checks, the method replaces the draft's exact readable-alias grants and returns written-file bytes, checkout identity and artifact projection. Selection membership is a separate operation. The byte limit on diff replies governs presentation rather than the saved evidence. A failed write or CURRENT update retains the completed files; later revision and cancellation failures also retain completed filesystem effects. Opened snapshot handles are released.

The SDK method `DraftRuntime.readGitArtifact(alias, signal)` reads an exact alias from that draft's latest publication grant. Catalog registration follows published artifact order; the manifest must be registered before any MAP or patch alias is available. Unreadable artifacts produce readiness warnings, with at most 20 individual warnings per snapshot and a count of omitted warnings. Reads check the registered manifest's snapshot, repository, checkout and creating draft, then read the body through a no-follow output capability. Configured credential paths and explicit workspace exclusions remain denied. Historical bodies remain readable after HEAD or working-tree changes under the same checkout identity. A successful new publication revokes older read grants; replacement during a pending read returns `gitArtifactAdvertisementChanged`. Catalog records belong to the workspace, while grants belong to the draft.

`DraftRuntime.manageSelection` accepts exact `_git_data/...` aliases for add, remove, set and preview in full mode. Insertions and previews require the latest publication grant; removal can use a selected historical alias after that grant has been replaced. Artifact aliases support neither fuzzy/folder lookup nor codemap or slice representations. Full clear removes artifact selection; codemap-only clear retains it. Selection commits before reply construction and response-size admission. Selected artifacts contribute checkout ownership when no ordinary files remain selected; unreadable or unauthorized artifacts cannot establish publication ownership.

Git MAP bodies are ordinary full-file blocks in `file_contents`. Selected patch bodies appear in `git_diff`, in selection order, joined by two newlines. Selecting both a whole patch and per-file patches includes both bodies, even when their content matches. Artifact bodies and identities are recorded with their byte spans; MAP records also identify their complete framed block. Integrity verification checks the saved packet, and current verification checks the stored artifacts under live root and checkout authority rather than requiring the current HEAD or working tree to match the snapshot fingerprint.

Live selection views, material inspection, previews, budget measurements and final export reacquire selected artifact bodies through the catalog. Reusing a snapshot ID can replace its files; selection keeps the same aliases while observations use their current authorized content. Reacquisition preserves selection order and revision. Export captures those bodies and checks them again before publication; a change during export rejects the packet. Terminal draft inspection retains the final complete capture after releasing its workspace lease. Saved integrity verification uses delivered bytes, while current verification detects later changes to stored artifact bodies.

Publication options require `scope: all | selected`. With selected scope and no explicit pathspecs, acquisition uses the draft's current full-file and slice selections; a slice selects the file's complete Git diff. The native helper converts selected absolute paths within the checkout to sorted, deduplicated relative paths and literal Git pathspecs. Codemap-only entries do not contribute paths. Statistics retain exact selected-path membership. A checkout with no selected paths produces an empty selected snapshot with null requested paths and no patch bodies. Explicit pathspecs take precedence over the scope option.

`publishGitSnapshot` returns a `single` publication for one admitted checkout, or a `multiple` publication for an implicit target containing several checkouts. The multiple result retains frozen repository order and includes successfully written snapshots plus RPCE's per-repository and aggregate replies. Up to three repository operations run concurrently. The output-root owner serializes writes, CURRENT updates and retention. Selected paths belong to the longest containing repository root; repositories with no applicable selected or requested paths return an empty reason and create no snapshot. A repository acquisition or write failure becomes that repository's error while successful siblings remain available. Aggregate repository count includes skipped and failed repositories; totals include successful diffs. Cancellation, revision changes and frozen-target identity changes reject the final reply. Completed filesystem effects remain.

`resolveGitSnapshotID` requires an admitted output-root capability and applies RPCE's rules for names and collisions. It creates no directories and replaces no files. `prepareGitPublicationMetadata` supplies the source commit-graph arguments and linked-worktree metadata used by snapshot manifests. The caller supplies an already authorized checkout path; publication revalidates its repository identities around acquisition.

Replies for publication from a linked worktree identify the current checkout and main checkout, their branch names and HEAD hashes truncated to seven characters. A detached checkout has an empty branch string; failed metadata queries omit the corresponding fields. Main-checkout resolution uses parsed worktree descriptors and validated `core.worktree` settings, including repositories with a separate Git directory. Snapshot manifests use the main root known from filesystem layout; reply metadata can also use the main root established by Git's listing. Routing warnings use the declared `root` and the checkout's absolute `worktree` path. Metadata runs through supervised read-only Git commands, and cancellation joins those commands before publication settles.

Repository admission and revalidation use the same normalized worktree descriptors as reply metadata. Bare entries are excluded, paths pointing to a shared Git directory are mapped to the resolved main checkout, and equivalent standardized-path aliases are collapsed. Conflicting aliases fail parsing. Requested checkouts still require current advertisement, an admitted advertising checkout and matching common-directory identities.

Queries retain worktree/Git-directory identities before and after execution. Path-bearing log/blame requests pass the workspace's policy checks. Diff discovers endpoint metadata before authorizing returned bodies. Its live source bytes are read through no-follow native capabilities and copied into a private worktree for Git's body comparison, including authorized attribute controls. The process supervisor owns execution, cancellation and child settlement. Git hooks, filesystem monitors and Git network-fetch paths are disabled. Log, blame, show and diff disable Git's textconv path. Git clean/process filters can execute configured programs, so repository Git configuration must be trusted. Invalid UTF-8 output fails with `gitOutputUndecodable`; failed commands return `gitQueryFailed`. For malformed status records, `gitStatusMalformed` includes RPCE's diagnostic. The complete encoded result must fit `maxOutputBytes`, otherwise it returns `outputBudgetTooSmall` and the required byte count.

Diff acquisition captures its fingerprint before statistics and patch bodies. Working-tree and staged comparisons hash the bytes from porcelain status, the resolved base revision, and each changed path's size and modification time; unavailable metadata contributes the source's `missing` marker. Unstaged comparisons use the `INDEX` fingerprint, while revision comparisons use their revision specification. Acquisition retains the complete permitted statistics, combined patch and per-file bodies before reply projection or response-size checks. Metadata reads use no-follow repository capabilities, and cancellation joins the owned Git processes.

### Search and output budgets

Search modes are `path`, `content`, and `both`. Literal/PCRE2 queries retain whitespace. MCP and Pi discovery-agent inputs default to literal content search with case-insensitive substring matching, empty filters, zero context, non-count-only output, and a null continuation. Glob queries default to path mode and use case-sensitive `path.posix.matchesGlob` semantics with neither text-query flag. Root, directory-prefix, include/exclude-glob, and extension filters run over admitted inventory paths before acquisition.

The configured ripgrep executable must support PCRE2 and have an audited build record. Path matching streams NUL-terminated relative paths, so embedded newlines remain path data. Content matching uses private ordinal-named files containing previously authorized bytes. Only CRLF and CR become LF in this search view; the BOM is retained. Ripgrep receives `--no-config`, `--encoding none`, explicit PCRE2/literal/case/word flags, and deterministic ordering. It never traverses source roots. Inputs are removed only after child settlement. A terminal summary must agree with the streamed match counts before results become usable; missing, malformed, or inconsistent records fail the search.

Search returns one complete grouped record per matched file, with original line numbers and terminators. Adjacent/overlapping context is merged by source line number. `occurrences` counts path and content match occurrences for the requested modes; each file also separates `pathOccurrences` from content `occurrences`. `matchingLines` counts distinct source lines with content matches, `matchedFiles` counts files matched by either mode, and `returnedMatchingLines` counts matching lines represented on this page. Count-only requests retain no snippets and return complete aggregate counts. Binary/undecodable content is reported in limitations. The adapter streams ripgrep output, retains one current file's context and a bounded page prefix, and continues counting after that prefix fills.

Continuations bind the complete query/filter/read arguments, inventory digest, runtime generation, policy digest, relevant source identities, and ordered position. Changing those request facts rejects the token. Physical reads revalidate controlling policies and source bytes; continuations cannot substitute newer source. A response cap may change between pages because it does not change query identity.

`maxOutputBytes` measures the actual UTF-8 JSON serialization of the application result, including metadata and continuation. `pageResult` accepts a rendering callback so adapters can include their result representation in that measurement. Omitted complete records produce a continuation. A single oversized record produces `recordTooLarge` with its required size and remedy. If metadata or that diagnostic cannot fit, `outputBudgetTooSmall` returns only its code and required size; this control diagnostic is the cap exception. These caps are presentation limits, separate from any final export allowance.

## Drafts and material ownership

`WorkspaceHandle.createDraft(request, signal)` registers a freshness barrier and acquires required sources, documents, and patches before returning a `DraftRuntime`. Its request is cloned, validated against the closed `ContextBuildRequest` schema, and frozen. Task, constraints, copy preset, stored prompt catalog, prompt duplication, purpose, required representations, documents, patches, discovery hints, allowance, and output name are immutable. A library draft object is its owner's capability; its printed ID is an inspection identifier rather than an independent authorization token.

Each draft retains a workspace operation lease. Physical preparation and finalization fork separately owned operations pinned to its discovery inventory and root identities. Explicit workspace registrations provide additional captured records. Closing a public workspace handle leaves admitted draft work usable. Runtime closure rejects new admission, cancels draft preparation, joins finalization and operations, and then closes workspace and process owners. Exploration reads and selected-tree projections have no mutation access to the material store.

## Public selection and explicit registration

`manage_selection` uses the native source parser, candidate resolver and selection mutations. Its defaults are `op=get`, `mode=full`, `strict=false`, `view=summary` and `path_display=relative`. Paths may identify files or directories through root aliases, relative paths or absolute paths. Promote and demote accept files; slice inputs support the source range aliases and terminal `#L` syntax. Full add preserves slices, full remove retains manual codemaps, codemap-only add and demotion disable automatic mode, and promotion retains it. Set rejects invalid inputs even when strict is false. Preview prepares selection and costs at the current revision. Required material, revision, cancellation and freeze checks apply before committing the prepared selection. Selection commits before native reply rendering and response-size admission. Cancellation, rendering failure or an oversized reply after commit leaves that selection in place; get or inspection retrieves current state. Replies identify their captured revision even if a later mutation advances it. Preview and get never mutate selection. An optional `expectedRevision` asserts the caller's revision; omission captures the owning revision at admission.

Strict add/remove failures for unmatched paths report loaded roots and accepted path forms, including up to two absolute paths outside those roots. Strict preview requires a rendered file or slice in its projected reply; codemap membership with no rendered body does not satisfy that check. Failed promotion/demotion prefixes collected diagnostics with `Invalid selection inputs:`. These failures retain the committed selection.

Selection replies list implementation entries before rendered codemaps. `summary` separates full-file, slice and codemap counts and their token estimates; `total_tokens` sums those selection estimates. Slice metadata uses `start_line`, `end_line` and an optional description in both `files[].ranges` and `file_slices`. `root_path` is the declared root label, and `path_within_root` is its relative file path. Views are `summary`, `files`, `content` and `codemaps`. The `codemaps` view filters the rendered files, slice metadata and selection totals to codemaps while retaining readiness diagnostics. Complete-packet `measurement` remains separate from these selection-only estimates.

The `content` view supplies source-formatted `File:` blocks with language fences and described slice labels. Slice assembly uses the whole captured file after checking its raw identity, executable mode and decoding against the selected material. Rendered codemaps retain their complete presentation text.

Explicit acquisition can register an ignored regular file in the workspace catalog. Source reads remain confined to the admitted root and protected paths remain denied. Registration commits after confined byte acquisition and before structural extraction. Optional codemap selection commits its captured membership before requesting the presentation. A rejected set or cancellation before selection persistence can leave a managed-only record with no selected material. Exact lookup and read can access that record; ordinary directory expansion, matching, tree, search and graph contributions exclude it. Selected trees include selected managed-only records and their ancestors. Workspace refresh rechecks registered files and their policies. Root-owner closure ends live catalog access.

Selection replies share a 10,000 ms allowance for codemap readiness. Admission, rendering and cleanup can take additional time. Workspace-owned requests retain shared extraction separately: releasing one request leaves another retainer's work running, and the last release cancels demand and joins its cleanup. An already admitted artifact build can finish and persist after its observers cancel. Unresolved presentations appear in `code_structure.pending_paths`; terminal non-renderable results appear in `unmapped_paths`. Pending does not promise that work remains retained. A later get requests the current presentation again and can complete the selected material without advancing the selection revision. Pending material makes the packet measurement incomplete and blocks publication; saved bundles contain settled material only.

Native tree and structural exploration use the operation-owned bridge. Closing or cancelling the operation joins admitted rendering before releasing its lease. The tree result contains RPCE-rendered text, root count, note and a continuation bound to captured inventory and request/selection identity. Response caps page complete rendered lines; depth cutoffs and automatic tree reductions are separate from response paging. Selected markers derive from full/sliced source selection; inferred and explicit code-map material are not marked as selected implementation.

Source selection requests identify root-qualified paths. Admission resolves them against the pinned inventory, reads their exact bytes, and stores the raw identity and Git executable mode with the representation. `full`, `slices`, and `codemap` are mutually exclusive per root-qualified path. Upsert replaces the entire representation. Requested slice ranges and descriptions remain recorded; valid overlapping or adjacent ranges are normalized for rendering. Invalid endpoints and empty slice lists fail. Rendered codemaps use a ready retained artifact's Swift projection and retain its canonical key. Explicit codemap selections retain supported files whose extraction produces no renderable codemap, including ready-no-symbols, parse-failed and oversize artifacts. Optional codemap selections also retain undecodable files with their raw identity and terminal decoding outcome. Their selection replies report `code_structure.unmapped_paths`, exclude them from rendered `files` and `blocks`, and keep their membership and artifact key in the saved manifest with no body spans. A later explicit codemap request completes a registered pending extraction against the captured source identity. Full files, slices and caller-required codemaps require decoded text; failed admission leaves the committed draft unchanged.

Source records identify `selectionOrigin` as `explicit` or `inferred`. Required sources are explicit; inferred sources are optional codemaps. Drafts start in `automatic` mode unless `requiredSources` contains a codemap, which makes the draft manual. Automatic selection follows type references from the file's complete syntax artifact, even for slices, one hop within the same root, with NFC-normalized, case-preserving matching. All ambiguous definitions are eligible unless a name has more than 4096 definition candidates before seed exclusion. Selected seeds are excluded. All eligible targets are retained and accounted for, including when the packet exceeds its allowance.

Full/slice upserts preserve mode and promote an inferred path to explicit selection. An optional codemap upsert enters manual mode and removes inferred codemaps. Removing an inferred-only or absent path is a no-op; removing an explicit source may leave its inferred codemap if another seed references it. `clearCodemaps` removes optional codemaps and enters manual mode. `clearSources` resets source selection to `requiredSources` and its initial mode. Both retain required representations, documents, patches and the current prompt; a required codemap keeps its draft manual. A mode change advances revision; genuine no-ops preserve revision and inspection order.

Source mutations prepare the complete explicit/inferred candidate before committing. Inferred acquisition failures commit nothing. Expected source/representation failures return `automaticCodemapUnavailable` with the inferred target's `source: { root, path }` and original `cause` code; cancellation and lifecycle failures retain their original classification. An editable draft can use manual selection for unavailable optional representations. Adopting changed source or policy requires a new authorized snapshot.

Documents have distinct local and supplied variants. Local documents use the same root, inventory, and policy checks as source. Supplied documents retain complete strict-UTF-8 caller text and an asserted origin, which never authorizes a read. All documents and requested patches are immutable required material. A denied local request fails during acquisition. It is not converted to supplied text.

`DraftUpdate.mutation.kind: "addDocument"` accepts a `suppliedDocument` after draft creation and appends it without changing the original request. Document IDs must be unique across initial and added documents; duplicates fail with `duplicateMaterial`. Text and origin must be lossless UTF-8 without NUL. Revision, cancellation, freeze and response-cap checks apply before commit. Admission reports the complete packet measurement; over-budget documents are retained and block publication. Saved records retain the admitted document and exact body spans. Bundle verification checks their bytes and identity.

`update` prepares I/O before committing synchronously. Commit checks the submitted revision, cancellation, runtime/draft lifetime, editable state, and whether any finalization freeze occurred during preparation. A blocked manual finalization may reopen editing, but preparations that crossed that freeze remain invalid. Identical state-setting preserves the revision. Required source removal or representation changes fail with `requiredMaterialMutation`; stale revisions return `revisionConflict` and the current revision.

The mutation receipt contains the committed revision, codemap mode, changed-item costs, fixed overhead, known complete/incomplete measurement, allowance, remaining amount or excess, and unresolved diagnostics. Changed-item costs cover every effective addition, removal, representation or `selectionOrigin` change; zero cost means the ID is absent afterward. An explicit-to-inferred transition reports the remaining codemap cost. The minimum receipt must fit before commit. Detail omissions are explicit and can be recovered through paginated cost inspection. `inspect` provides metadata, item costs, and material content. Metadata includes a prompt item with the complete current literal text. Material pages contain complete line records and a continuation bound to the material digest; metadata/cost pages bind draft identity, revision, records and packet measurement. Completing pending codemaps invalidates older inspection continuations even when the selection revision remains unchanged. A prompt record that exceeds the caller's output allowance returns the existing oversized-record diagnostic.

Inspection is asynchronous and accepts a caller cancellation signal. Each metadata/cost response captures its revision, prompt, materials and admitted inventory before awaiting native tree rendering. Runtime-owned data-only rendering remains available after terminal finalization releases the draft's workspace lease. After map preparation, an update rechecks revision, cancellation and freeze before committing; competing updates can finish preparation in either order, but only one can commit at their shared expected revision.

A `batch` mutation supplies an ordered non-empty `edits` array of source upserts, removals, slice edits and clear operations. All edits use one prepared candidate; inferred codemaps are derived from its final seeds. The whole batch advances revision once when its effective state changes. Acquisition, required-material, cancellation, freeze and minimum-receipt failures leave the committed draft unchanged. `draft_preview` prepares the same edits and returns candidate metadata, costs and diagnostics at the existing revision. Its reply must fit the response cap, and it never changes committed state or inspection continuations.

The `slices` mutation edits one selected source through the same revision and receipt transaction. `add` coalesces ranges with existing slices; `setPaths` replaces ranges for that file; `remove` subtracts ranges, with an empty range list removing all its slices. Removing the last slice retains the selected source as a full file. Inclusive ranges retain nullable descriptions; adjacent or overlapping ranges merge distinct descriptions in source order using `"; "`. Required representations remain fixed, and failed preparation commits nothing.

`ContextBuildRequest.enhancementMode` captures `fullRewrite`, `augment` or `preserve`. Prompt state begins as `task`; `constraints` remains a separate fixed caller input. `prompt` exposes get, set, append and clear. Mutations use the same expected revision, freeze/cancellation check and synchronous commit as source updates. The complete encoded prompt reply must fit its response allowance before committing. Setting identical text is a no-op. The mode controls discovery instructions, not a separate runtime authorization policy. The final packet delivers the current prompt verbatim; the coordinator records retain the original request text.

`ContextBuildRequest.initialSelection` captures mutable starting sources and `codemapMode`. Automatic mode accepts full files/slices; manual mode also accepts codemaps and can begin with no codemaps. Required codemap evidence selects manual mode. Initial sources are ordinary explicit selections with `required: false`, unless the same exact representation is also required. Duplicate initial paths and conflicts with required representations fail admission. Saved requests record the original starting selection; verification requires final membership only for caller-required evidence.

## Accounting and deterministic rendering

`utf8-21-over-80-v1` uses integer arithmetic: estimated units are `floor(21 × bytes / 80)`. The measured recipient file is the complete emitted `context.md`. The request supplies numeric `budgetUnits`, the complete-packet limit. Scout input receives `max(0, budgetUnits - 1500)` once, using RPCE's startup reserve. `handoff.md` and `manifest.json` have integrity identities but consume no assembly budget. Draft admission rejects requested `budgetUnits` above that configured maximum with `assemblyBudgetExceeded`, before acquiring required material or starting discovery. Requests at or below the maximum retain their numeric limit. Initial metadata reports the configured maximum, the packet limit and the amount available to discovery.

`renderBundle` is pure and shared by mutation accounting, validation, finalization, and integrity verification. It orders materials independently of mutation order and measures complete headings, paragraphs, lists, fences, bodies, and final instructions. Each patch summary names its ID and root, comparison kind and scope, requested and resolved revisions, worktree paths, coverage and exclusions. Complete receipts, payload identities, per-path policy and target evidence are recorded in the manifest. Item estimates are individually rounded; total units are computed from the complete packet rather than by summing rounded item estimates. Prompt state starts as the original task, so publication does not require a separate handoff mutation. Unknown or exceeded allowance and source-comparison mismatches produce blocking diagnostics, with complete cost information retained.

The packet uses RPCE clipboard sections in default order: `file_map`, `file_contents`, `git_diff`, numbered meta prompts and `user_instructions`. The map combines the native adaptive tree and retained codemap presentations. Full sources, slices and documents use native `File:` labels, language fences and slice annotations. Supplied document labels include their role, origin and ID; local documents use root-qualified source paths. Caller constraints occupy an explicit meta prompt titled `Constraints`; the final user section contains the current literal prompt. Selected required patches retain complete raw bodies in the Git section. Empty sections are omitted by native packaging. Separators and annotations are outside material spans. Every span records a UTF-8 byte offset, length and digest. Source and document records also retain their complete native block spans.

The schema-version-13 manifest records original request content/digest, enhancement mode, initial selection, current prompt, historical inventory evidence, restrictions, codemap mode, all material records/spans and selection origins, file identities, accounting, decoder identity, and verification checks. Full-file and slice records include a `frame` span covering their native-formatted block; raw-body spans locate exact evidence within it. Normalized slice ranges retain their coalesced descriptions. Local document records retain both raw-source and delivered-text identities. The schema-version-5 inventory captures the decoder policy, each file's decoding outcome, discovery/managed-only visibility, pending structural acquisition, and the native ignore-policy authority, settings and controlling inputs. Runtime sequence numbers for inventories, draft revisions, timestamps, and random draft IDs are excluded from rendered artifacts.

## Patch acquisition and coherence

`suppliedPatch` records complete caller text, asserted origin, comparison identifiers, coverage, and target raw identities/modes. Its bytes and declared path authorization are verified. Source coherence requires usable matching target evidence for every selected source in the associated root. Inferred sources follow the same coherence rules. A mismatch on an inferred source can be resolved with `clearCodemaps` followed by explicit codemaps with matching target evidence. A scout must make that correction before completing its job; manual draft callers can make it before finalization. Integrity preservation does not prove an external producer's comparison completeness.

Local patch requests name a declared root within a Git worktree, an explicit commit or empty baseline, comparison kind, and all-paths or prefix-path scope. Git resolves the owning checkout from the declared root. Tree and index entries are limited to that root; coverage, target evidence and policy paths are root-relative. Rendered patch paths are repository-relative so they apply from the checkout root. The repository receipt records the actual owning worktree identity. Commit references are resolved once to object IDs. Worktree targets come from confined live reads; staged targets come from captured stage-zero entries; commit targets come from endpoint trees. Repository/worktree identities, HEAD when present, applicable index facts, resolved endpoints, policy inputs, target byte/mode evidence, changed paths, exclusions, and the complete patch digest are recorded. Relevant executable mode is Git's owner-executable bit, represented as `100644` or `100755`.

Git processes use argument arrays, an explicit cwd, a restricted environment, literal pathspecs, no pager/replacement objects/lazy fetch, disabled optional locks and fsmonitor/hooks, and disabled external diff/textconv. Neutral scratch comparisons stop repository discovery above the private scratch tree. Each side is explicitly absent or a regular-file byte/mode value. Present pairs use `a/path` and `b/path` with `--no-prefix`; additions/deletions use the original path and `/dev/null` from the present side with explicit `a/` and `b/` prefixes. The fixed diff options include full-index binary output, three context lines, Myers, no renames, and no indent heuristic. Differing sides require exit 1, empty diagnostics, and nonempty patch output. An exit-1 missing-input error fails these requirements.

Participating authorized symlink/gitlink entries fail explicitly; entries outside the comparison scope or excluded by policy do not participate. Unmerged index entries fail during index decoding. Included untracked paths are enumerated through the confined policy reader, which also detects new comparison members during final checks. Staged/commit comparisons require all selected regular sources in the root, including supporting files outside a restricted patch scope, to match target bytes and mode. Unselected worktree dirt does not independently reject those comparisons. Final revalidation regenerates local patches against recorded endpoints and requires receipt and digest agreement.

`ContextBuildRequest.copyPreset` is `standard`, `plan` or `codeReview`. `storedPrompts` supplies the captured catalog as UUID, title and literal content. The retained preset constructors and meta-selection method select the Plan architect UUID `8e81aac2-79ce-4897-a59e-efd81eebb7e9` or Review UUID `d7f1b2e4-3c5a-6b8d-cf8e-1f5d0e2a4c6b` in catalog order; UUID matching is case-insensitive. Standard selects no saved prompts. Missing catalog matches yield no saved block. Source-specific prompt IDs take precedence over the meta-inclusion flag. Caller constraints follow the selected saved blocks as an explicit `Constraints` meta prompt. All delivered role bytes count toward complete-packet measurement. `duplicateUserInstructionsAtTop` is an explicit request setting. When true and the resulting prompt is nonempty, native assembly prepends its complete user-instruction block before ordered context sections and retains the ordinary final block. The source default is false. Both copies count toward fixed overhead and complete-packet units; material/tree spans include the prefix offset.

## Finalization and verification

The native snapshot writer requires an output-root capability and writes beneath `_git_data/repos/<repoKey>/<snapshotID>/`. Source snapshot-ID normalization establishes its relative path. A null or `auto` ID uses the local date and minute, followed by a numeric suffix when that name already exists. An explicit named snapshot replaces the previous directory before new files are written; handles for the previous directory become stale. Artifact files use descriptor-relative parent traversal and atomic file replacement; repeated paths apply in call order. Parent and leaf symlinks are refused. Every file write revalidates the bound root, snapshot directory and containing directory, returning `rootChanged` or `outputChanged` when ownership changes.

`writeGitSnapshotCurrent` updates that snapshot's repository-scoped `CURRENT` pointer. It writes a relative symlink; if link creation fails, RPCE's pointer-file recovery writes the ID atomically and returns the link failure's errno. The bridge logs that recovery as `gitCurrentSymlinkFailed`. `readGitSnapshotCurrent` reads both pointer forms using the retained RPCE reader. If a symlink's target is missing, the result is absence; an ID stored as text is returned even when the named snapshot is missing. Snapshot-file reads require the same output-root capability, reject symlinks and traversal, and verify the returned bytes against their SHA-256 and byte count. A later pointer failure or cancellation retains completed snapshot files.

Git-snapshot capabilities permit mutable artifact files; final-bundle capabilities permit exclusive fixed-name writes and manifest publication. Each operation accepts its own capability kind. A failed snapshot write retains earlier completed files and reports the native failure and errno. Ordinary failures attempt temporary-file cleanup. Cancellation retires and joins the owned native worker; completed files remain available for diagnosis.

Native maintenance operations limit each workspace to 25 snapshots after publication. At workspace open, a full cleanup also expires snapshots older than seven days, provided six hours have elapsed since the last full cleanup. To enforce the count, maintenance sorts snapshots by generation time, repository key, then snapshot ID. Retained entries are stored in `retention-index.json`, version 1. `maintenance.json`, version 2, records the last full cleanup. Unsupported metadata versions return `unsupportedSnapshotState` before files are changed.

Workspace admission settles the initial maintenance call before returning its capability. Mutations for the same canonical output directory, device and inode share a FIFO queue, including declarations with different source roots. Cancelling a queued caller releases that caller while later mutations still wait for earlier work. Active mutations receive the caller and runtime shutdown signal and settle their owned work before releasing the queue. Maintenance completion is logged as `workspaceSnapshotMaintenanceCompleted` with its workspace key and outcome.

Each output-root queue owns one native worker and retention cache until runtime shutdown. Mutation admission reopens the captured output identity before supplying the worker and output handle to the callback. Workspace admission and subsequent mutation callbacks share that cache, so a stale on-disk retention index cannot replace it during the worker's lifetime. Cancellation or worker failure remains a failed request; a later mutation closes the retired generation and opens a new one against the same captured root identity. The new generation rebuilds its cache through the source's persisted-index or snapshot-enumeration rules. Admission logs `snapshotMutationAdmitted` with the output-key digest and native generation.

`finishGitSnapshot` releases a snapshot run's directory descriptor and invalidates its write handle. It retains the completed files and output-root capability. Callbacks must finish opened runs after their writes settle; worker retirement releases run descriptors for interrupted work. Runtime shutdown joins mutations and closes their native workers and cached output handles.

Explicit owner disposal deletes snapshots with matching recorded owner UUIDs. Completed snapshots remain available across build completion and process exit. After deletion, affected repositories update `CURRENT` to their newest remaining snapshot. If deleting the last snapshot leaves a dangling symlink, RPCE's cleanup retains that link and reads it as absence. Filesystem operations use the admitted output-root capability and no-follow traversal; the `_git_data` root remains in place after pruning.

`finalize` freezes one revision and owns its publication claim. It reopens roots, revalidates every delivered local source/document and its controlling policy, verifies supplied material and comparisons, renders and measures the packet, writes fixed filenames exclusively, and checks complete readback. It repeats input checks immediately before claiming publication and asks the native bridge to publish and sync `manifest.json`. Ready returns the actual directory and manifest. A correctable manual validation failure returns blocked diagnostics and reopens editing with its lease retained; stale input, cancellation, or publication failure leaves the draft terminal and releases its workspace lease before the result settles, while inspection data and any candidate files remain available.

`cancelFinalization` returns `cancelling` before the claim and prevents publication. After the claim it returns `publicationInProgress`; the existing result promise and runtime closure join the ready/failed outcome. A claimed publication has its own non-aborted native request signal. Write/readback/sync failures never become ready. Partial files and uncertain publications remain available for explicit diagnosis, with no automatic overwrite or cleanup.

Worker closure or a malformed response after the publication claim returns `publicationUncertain` with sanitized worker-close facts. The candidate directory remains available for explicit integrity/current verification. An exclusive-create refusal remains a definite failure.

`verifyBundle(directory)` validates the saved manifest, unique root-qualified inventory paths, file identities, spans, required representations, rendering, and accounting using bundle bytes only. It needs no runtime, native executable, search engine, Git, or model configuration. Integrity reconstructs inferred membership from the saved inventory and explicit selections, requires exact membership equality in automatic mode, and rejects inferred records in manual mode or explicit codemaps in automatic mode. It establishes internal consistency, not authentication of the bundle's author or filesystem authorization.

Source framing is parsed against the captured path, extension, normalized range labels and raw-body spans. Rehashed blocks with incorrect source labels or fences fail integrity verification. Live acquisition retains the native formatter's immutable output; inspection, accounting and publication use that captured block. Saved verification reconstructs the same typed block by parsing archived bytes.

Final packet maps use RPCE's adaptive renderer with selected-root filtering, legends and operation-specific codemap markers. Full files, slices and local documents mark selected implementation paths; automatic mode also marks its resolved codemap paths. Ready selected codemaps receive plus markers, as do ready selected seed projections in automatic mode. Neighboring admitted files can appear without being selected or having a codemap presented. Managed-only files enter through explicit selected paths or presented codemaps; the native trie supplies their ancestor folders. The complete map, including section framing and legends, counts toward packet measurement.

Manifest v12 records the exact Standard/Plan/Review preset projection, native tree input and the exact tree-body span. Saved verification checks the preset against its closed source contract and the tree input against the archived inventory, material representations and mode, then checks the captured bytes and complete packet accounting. It verifies the captured presentation rather than executing the native renderer. Current verification additionally replays the recorded tree and clipboard assembly through the configured native renderer and returns `presentationChanged` on a mismatch. These checks retain historical selection and inventory; they do not rebuild either from current workspace membership.

Both verifiers open each bundle component nonblocking, check that its descriptor names a regular file, and close the descriptor after reading or failure. A nonregular component returns `nonRegularBundleFile`. Current verification passes its combined caller/shutdown signal to descriptor reads and checks cancellation around acquisition and reading.

`verifyCurrentBundle(directory, runtime, signal)` first performs integrity/schema verification, then admits an internal verification operation. It never installs recorded inventory as current workspace membership, warms unrelated indexing, or publishes membership. The runtime validates the recorded declaration, combines recorded restrictions with current cache/output/credential denies, and reopens every source/output root against recorded aliases, canonical paths, and filesystem identities. Delivered local paths retain their original controlling-policy checks. Codemap revalidation compares each freshly returned native key with the recorded key. Comparison-scoped worktree enumeration remains necessary for live comparisons; unrelated directories are otherwise not enumerated. Admission, cancellation, operation closure, and runtime shutdown use the existing runtime and process owners. Neither verifier edits saved files or certifies continued freshness after its checks.

Current verification retains historical membership and revalidates delivered material rather than deriving a new dependency graph. It checks slice endpoints against the acquired source's actual line count and compares each saved body with the normalized slice from those bytes. Integrity decoding requires supplied-patch targets and coverage to match the frozen input, with a null repository receipt.

## Discovery and client ownership

`SmipRuntime.createClient(runner)` creates a client owner for public workspace/draft IDs and a `JobRegistry`. The runner is a transport-neutral capability receiving the caller's purpose, task, constraints, discovery hints and root names, an admitted-state `initialContext`, scoped tools, cancellation and progress. A null runner supports manual operations. Runtime closure closes its clients before the remaining workspace/process owners. Client closure rejects new work, cancels jobs and admitted manual operations, joins settlement, and releases workspace leases. Terminal manual finalization, whether ready, failed or cancelled, and terminal jobs release their draft leases while retaining inspection data; blocked drafts stay editable and leased.

`initialContext` is captured after required and inferred material admission and before scout dispatch. `DiscoveryInput.tokenBudget` is the numeric scout allowance after the source reserve. It identifies draft/revision, inventory, mode, all roots, explicit selections, IDs for inspecting documents and patches, inferred count/item units and complete-packet accounting. Inferred paths are available through the overview and paged inspection. The Pi adapter presents this observation as raw multi-line data, followed by an Assignment section containing the remaining input as JSON. Task and constraint strings retain their exact values.

The initial file map tries full, depth-three full, directories, depth-three directories, then selected-only views, with root names when none fits. The tree fit check uses 6000 estimated units before legends and notes. Its sibling cap is 100, raised to the selected-child count. Stars identify explicit full/sliced files; pluses identify delivered codemaps. Skipped inventory entries are omitted; directory, file and acquisition-failed entries remain eligible. Overview omissions affect presentation only; paged exploration supplies detail.

Builder admission requires numeric `budgetUnits` and a client-local request ID. The canonical digest includes the workspace handle and complete request. Duplicate input returns the existing job; conflicting input fails. Draft acquisition registers its freshness barrier and lease before admission returns. The runtime reconciles the workspace and acquires required material before discovery. The job transitions through discovery settlement and the existing draft finalizer; that finalizer owns the publication claim. Cancellation after the claim reports `publicationInProgress` and leaves the claimed operation to finish.

`context_builder_wait` observes one job for a caller-selected duration. Its cancellation and timeout leave the job running. Progress has monotonically increasing sequence numbers, and callbacks cannot change execution. Terminal snapshots remain retrievable until client closure. A blocked snapshot names an inspectable builder draft; public updates and finalization accept only caller-created manual drafts.

The Pi adapter launches one Node process through `ProcessSupervisor` for each run. Private LF-delimited JSON messages include generation/job identities. Closed schemas validate tool calls, evidence and terminal messages. The parent injects the pinned draft and operation, rejects unknown/retired generations and duplicate calls, and closes admission immediately on cancellation. Child closure alone cannot settle a pending parent tool. A terminal response received with outstanding parent work is rejected.

Worker retirement cancels the job's operation before joining pending parent tools, including its physical native reads and search processes. Shared indexing and other operation owners remain independent. Records received after retirement cannot alter the discovery receipt.

Pi discovery configuration requires an absolute `promptPath` and an `mcp` reference or `null`. At each run's start, the parent opens the prompt file nonblocking, checks the opened descriptor is regular, reads with the run's cancellation signal, and closes the descriptor. It decodes strict UTF-8, checks the `# smip discovery v1` LF-terminated marker, and records the raw-byte digest before starting a worker. The worker receives that retained text for its controlled resource loader and constructs in-memory session/settings. Editing the file changes later runs while active runs retain their admitted text. Its base tools are the four exploration tools plus draft inspect/update/validate. It selects one physical model and rejects thinking clamping. The adapter observes the existing shared stream function's result promise for both ordinary and summary calls; it does not consume the stream iterator again or implement recovery. Retry, provider, compaction and transport settings are explicit, and cache warming is off. The parent assembles the receipt from typed preflight, assistant, prompt, completion and lifecycle facts, retaining received evidence after forced worker closure.

`discovery.mcp` is `null` or `{ "agentDirectory": "/absolute/path" }`. The directory must exclude group/other permissions and contain a regular, strict-UTF-8 `mcp.json` file. Each job retains the configuration read at its start; edits apply to subsequent jobs. Only configured HTTP servers and exact selected tools are authorized.

The `mcpServers` object requires at least one server. Server names start with an ASCII letter and contain only ASCII letters, digits and underscores. URLs use HTTPS, or HTTP on `localhost`, `127.0.0.1` or `[::1]`, with no userinfo. Each server requires `exposure: "hidden"` and at least one exact tool name with `"direct"` exposure in `toolExposure`. Optional fields are `headers`, Pi's `oauth` settings, `description`, a positive per-request `timeout` in seconds, and `type: "http"`. Header values and `oauth.clientSecret` accept literal values and native escapes: `$$` for a dollar sign and `$!` for an exclamation mark. Commands and environment-variable interpolation in those fields are rejected. Tool selection authorizes names; server-side read-only credentials or scopes limit the server's privileges.

MCP OAuth state is stored in `mcp-auth.json` and server logging notifications in `mcp.log` under the private directory. CLI/MCP hosts exclude that directory and the declared/physical targets of `mcp.json` and `mcp-auth.json` from source access. Library hosts must include those paths in `credentialPaths`.

Configured discovery can call the selected MCP tools and the exposed smip context tools. A failed tool-availability check prevents the next model request and fails discovery with `mcpToolsUnavailable`. Interactive sign-in must precede jobs; the worker never opens a login browser. Source access, draft mutation, budget enforcement and publication remain subject to smip's workspace and draft contracts.

`DiscoveryReceipt.mcp` is `null` when MCP is disabled. Otherwise it records the admitted file's raw-byte `configSHA256`, authorized server/tool names and hashed endpoint URLs. Readiness `ready` records the first successful availability check, registered tool names in `tools` and a digest of their declarations in `declarationSHA256`; `unavailable` records a failed check. Shutdown `dispatched` means the shutdown event returned with no observed handler failure; `handlerFailed` records an observed handler failure. `notObserved` in either field means no corresponding observation was received.

`workerClosed` establishes local HTTP connection release. Readiness and shutdown observations do not certify remote cancellation, acknowledged session deletion or complete SDK cleanup. Successful discovery requires MCP readiness `ready` and shutdown `dispatched` whenever MCP is configured.

Success requires one accepted prompt, prompt resolution, `agent_settled`, idle completion, a latest normal-stop nonempty text/thinking-only assistant message, joined observations, disposal and child closure. The parent validates these receipt facts and settles its own tools before finalization. The final assistant acknowledgement is diagnostic evidence; the committed prompt and selection remain the artifact authority. Recovered attempts stay recorded even if the SDK omits them from projected conversation state. Independent server identity can be unavailable, and local closure makes no claim about remote cancellation or billing.

Model registration consumes the validated configuration snapshot. Every locked credential read and write checks for executable configuration before key resolution or persistence. OAuth refresh uses Pi's serialized persistent credential storage. The credential adapter requires Pi 1.0.2 and the audited authentication module's exact source and declaration hashes; a mismatch fails with `unsupportedCredentialSDK`.

MCP hosts use the official 2.3.0 `serveStdio` factory and negotiation. Factories register handlers without storage or worker acquisition. The connection owns its client; stdin EOF joins application shutdown independently of transport closure. Shared TypeBox schemas feed `fromJsonSchema` and application validation. Each discovery runner supplies its result encoding to scoped tools for serialized cap measurement. Pi measures JSON text content and error metadata; MCP measures content, structuredContent and error flags. Error projection exposes stable codes, known revision/required-size fields and validated cache recovery targets. Failed or cancelled builder receipts carry the same validated `target`, or `null`, through library results, MCP `context_builder_result`/`context_builder_wait` and CLI `build` output. Cache corruption/conflict targets contain an explicit artifact or membership kind and a lowercase SHA-256 key. CLI recovery requires `cache invalidate --kind artifact|membership --key <sha256> --config <absolute-file>`; library recovery uses `runtime.artifacts.invalidate(key)` or `runtime.artifacts.invalidateMembership(key)`. Each invalidation removes only the named record. Read-range errors include the fixed source diagnostic; exception messages and arbitrary details remain private.

`@earendil-works/pi-codemode` is pinned directly to 1.0.2 alongside Pi 1.0.2. Pi imports the `MCP_TYPESCRIPT_PREAMBLE` declaration exported by that version; the installed-package test exercises this import through the actual discovery worker.

The embedded dependency identity and terminal receipt use `buildLockSHA256` for the SHA-256 of the package-lock.json consumed by the build. Installed packages may resolve a different transitive graph; its lockfile and audit are separate deployment evidence.

MCP factory and stdio host `closed` promises resolve after successful cleanup or reject after cleanup failure. EOF, server-close and signal shutdown join application and transport cleanup. Cleanup continues after a failure, then the CLI reports a sanitized failure on stderr and exits nonzero; protocol stdout contains only MCP messages.

The stdio host forwards protocol bytes through a host-owned Writable to shared stdout. After application work and any claimed publication finish, shutdown cancels the wrapper's pending writes and joins their rejected send promises before completing transport cleanup. Expected output cancellation is separate from output or cleanup failure. The wrapper closes while shared stdout remains open for its owner. Bytes already accepted by stdout cannot be retracted, and local write settlement does not prove peer receipt.

The compiler uses strict NodeNext application checking with `skipLibCheck: true`. This exempts internals of third-party declaration files: Pi 1.0.2's generated model declarations omit JSON import attributes, and Google GenAI's declarations reference an optional legacy MCP type. Application checking retains `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` and `verbatimModuleSyntax`. Runtime integration tests exercise the actual pinned packages.
