# Native and workspace contracts

This document describes the private bridge implemented by `native/Sources/SmipBridge/`, its TypeScript schemas in `src/contracts/`, its client in `src/native/bridge-client.ts`, and the workspace/exploration APIs. Native directory capabilities authorize physical access. Workspace services apply exclusions and generation policy before requesting that access.

## Process and framing

Launch `SmipBridge <generation>` with an explicit environment. The client creates a fresh generation for each process and serializes requests. Each request is a closed object containing `wireVersion: 1`, a nonempty `requestId`, `generation`, and a discriminated `operation`. The TypeBox schemas and Swift parser reject unknown fields and malformed values. Base64 must round-trip to its canonical encoding. Only byte `0x0A` separates records; Unicode line separators remain data inside JSON strings.

Responses repeat the envelope identities. A request produces zero or more `bytes` or `entry` records followed by exactly one `terminal` record. Bytes use base64. A source response becomes usable only when its terminal receipt agrees with the accumulated byte count and SHA-256. A directory receipt covers the entry count and SHA-256 of the concatenated UTF-8 sequences `entryKind + NUL + name + NUL`, in emitted order. Directory entries are sorted by their raw UTF-8 names.

Malformed UTF-8, invalid frames, unknown versions, mismatched identities, duplicate terminals, unexpected record kinds, inconsistent receipts, and premature process closure fail the request and retire the client. Retirement rejects queued operations, invalidates handles, and joins process closure. A normal source failure returns a `failure` result and leaves the process available. `NativeFailure` exposes its code and optional errno. `NativeWorkerFailure` exposes the exit/signal/spawn receipt and the affected source identity when one was supplied.

## Operations

- `describe` returns the thirteen supported extensions, strict decoder identifier, canonical bytes for each pipeline, parse limits, and regex configuration. `jitCapability` records compiled engine support; `jitExecution` records whether matching at startup used compiled JIT, was disabled, or found JIT unavailable under the automatic policy.
- `openRoots` admits existing absolute directories, resolving an explicitly declared root alias and returning its declared/canonical paths, device/inode, access kind, and generation-bound handle. Source and output capabilities have distinct access kinds. An optional expected identity supports reopening the same authority in another process; disagreement fails with `rootChanged`. Duplicate names or canonical paths in one declaration fail. Reopening an identity that the process already admitted with the same access kind returns that admitted capability after the fresh path and identity checks; it retains no additional descriptor, and a source capability is never returned for an output declaration or the reverse.
- `listDirectory` accepts a source handle and either `{ kind: "root" }` or `{ kind: "descendant", path }`. It emits each entry as file, directory, symlink, or other, then a complete receipt. Directory fingerprints must agree before and after enumeration.
- `readSource` accepts a source handle, relative path, and an expected raw identity or null. It emits exact bytes and returns their identity, the unchanged descriptor fingerprint, and the eligible canonical artifact key or null for an unsupported extension. Missing paths, denied access, special files, symlinks, and changed observations have distinct failures.
- `extract` accepts an extension, exact base64 bytes, and the expected raw identity. It verifies that identity before decoding. It returns a retained core outcome, its canonical key, and, for ready artifacts, the original Swift API description and sorted defined type names. Unsupported extensions produce `unsupportedExtension` at the bridge level; they are not empty artifacts.
- `beginExport` creates one fresh, private run directory beneath an output handle and returns a run capability. `writeExport` exclusively writes `context.md` or `handoff.md`; `readExport` reads either file completely and returns its identity. `publishManifest` exclusively writes `manifest.json`, syncs the file and directories, and returns the written identity. The application finalizer owns material verification and the publication claim. A failure after manifest creation that leaves durability uncertain is `publicationUncertain`.

## File authority

Relative paths preserve filename spelling and Unicode. They reject absolute values, NUL, empty components, `.` and `..`. Root names are case-sensitive ASCII identifiers beginning with a letter and continuing with letters, digits, `_`, or `-`.

Directory traversal uses descriptor-relative opens with no-follow semantics. A fresh directory description avoids sharing enumeration offsets or filesystem caches between operations. Leaf reads use no-follow and nonblocking flags, then require a regular file through `fstat` before reading. Root aliases and directory identities are rechecked; export operations also recheck the run directory's identity. No descendant symlink is followed, and a source handle cannot authorize writes.

The source fingerprint records device, inode, size, POSIX mode, and modification/change times obtained from the opened descriptor. Device, inode, and timestamp seconds are decimal strings; nanoseconds, byte size, and mode are integers. Device identifiers retain the platform's signed representation. The bridge compares every field around acquisition and independently hashes the acquired bytes. Consumers use the captured mode for comparisons involving executable permissions. This establishes an observed byte sequence, not a filesystem transaction or future freshness guarantee. Application finalizers must reopen and check delivered material through the same authority.

## Decoding and extraction identity

`smip-strict-utf8-v1` accepts exactly the UTF-8 byte sequences that survive decoding and re-encoding unchanged. It preserves a leading BOM as U+FEFF, newline bytes, Unicode spelling, and empty input. Invalid sequences return `decodeFailed`; repaired text is rejected. Tree-sitter's internal UTF-16 offsets are distinct from raw UTF-8 byte identities.

The existing outcomes remain `ready`, `readyNoSymbols`, `oversize`, `decodeFailed`, and `parseFailed`. Oversize reasons distinguish UTF-8 bytes, UTF-16 units, and lines. Grammar/query exceptions are operation failures, and a crash is a worker failure.

Swift constructs the sole canonical artifact key. Pipeline domain `codemap-pipeline-identity-v2` includes the required regex-engine fingerprint along with the retained decoder, grammar/query, version, flag, and limit fields. The fingerprint hashes sorted-key JSON under `smip-regex-engine-v1`, including the pinned PCRE2/SLJIT source identities, patch set, Unicode version, width, recipe settings, and resolved JIT policy/support/execution facts. Platform, compiler, and hashes of library artifacts are separate build evidence. The client validates the canonical bytes' digest rather than reimplementing their encoding.

## Ownership and cancellation

`ProcessSupervisor` owns each child from spawn through the `close` event. Callers provide executable, argument array, working directory, environment, and the supervisor's `terminationGraceMs`. It sends SIGTERM on stop, escalates to SIGKILL after that grace, and awaits closure of the process and its streams. Its JSON diagnostics contain opaque process identities and exit/signal facts, not command arguments or stderr bodies.

Each `BridgeClient` owns one serialized native child. Aborting a request retires that client and rejects its queued work; closing one client leaves other clients under the supervisor running. Shared indexing must have its own owner: cancellation of a waiter releases its interest rather than aborting another owner's bridge. Supervisor closure stops admission and joins every owned child. A failed operation is never automatically replayed.

## Workspace generations and exploration

`SmipRuntime.declare(spec, signal)` admits named source roots and the output-root identity before warming. `WorkspaceSpec` requires ordered roots, explicit prefix/glob exclusions, and an absolute existing output directory. Names and canonical root paths are unique. The declaration key includes source/output identities, exclusions, state-directory exclusions, and the ignore implementation version. Mutable `.gitignore` contents belong to each generation's separate policy identity.

Every permitted directory is listed through the bridge. Policy discovery reads `.gitignore` through the same confined reader, including control files ignored by ordinary ignore rules. Policy inputs contain exact text/raw identity or an explicit absence. Parent rules precede descendant rules. Each parent directory must be admitted by the effective ordered rules before its own control file is read. Mandatory/caller exclusions apply through every containing canonical root. Absolute denies match canonical source paths and equivalent paths through every containing admitted root's declared alias. Configured protected paths retain their declared spellings and include their existing canonical targets, including independently declared aliases. An absent optional credential file is denied at its declared path and at the physical path formed from its canonical existing ancestor plus the absent plain-name remainder, so creating it later beneath an independently symlinked parent cannot admit it. A dangling symlink or a remainder containing `.` or `..` components fails admission with `credentialPathUnresolvable`; current verification applies the same rule. No descendant source symlink is followed. A denied, unreadable, nonregular, or undecodable required policy input prevents complete enumeration.

`refresh(signal)` registers its barrier before waiting and returns the immutable publication satisfying that barrier. One owner serializes scans and coalesces later requests into a follow-up scan. A later scan's failure affects only observers still waiting for publication. Every scan rehashes permitted regular files. The immutable snapshot separates enumeration completeness, settled processing, per-file structural outcomes/acquisition failures, and skipped-entry reasons. `inventoryDigest` describes content and policy; `generation` orders observations within the owner. An incomplete enumeration cannot admit an exploration operation. After native generation retirement, a later explicit refresh joins that generation's closure and reopens source and output roots against their original declared/canonical paths and device/inode identities. Failed requests remain failed.

Workspace handles and operations hold separate leases. Closing a handle prevents further calls through that handle and releases its lease. It does not revoke another handle or an already admitted operation. Shared extraction retains its producing owner until the extraction settles. A consumer's cancellation releases its observation of another owner's extraction. Cancelling a refresh observer releases that observer without aborting the shared scan. Runtime shutdown aborts inventory owners before joining clients, then joins native work, pending admission and operation lanes.

`openOperation(signal)` pins the current inventory and policy. Tree/structure projections require no new process. The first physical read lazily opens an operation-owned bridge against the originally admitted root identities. Operation closure aborts its physical work and waits for all admitted calls and owned child closure. Selected-tree requests consume a caller-supplied immutable `{ draftId, revision, sources }` projection; the draft owner is responsible for supplying authorized selection data.

### Persistent artifacts

Artifacts reside at `v1/artifacts/<shard>/<keyDigest>.json`. The closed record schema contains `schemaVersion: 1`, Swift-produced `keyCanonicalBase64`, `keyDigest`, `outcome`, `projection` only for ready outcomes, and `recordSHA256`. The checksum covers recursively key-sorted JSON of every other field. Array order is retained. Reuse validates the schema, canonical base64/key hash, correspondence to the current Swift key, checksum, and projection/outcome agreement.

Insertion writes and syncs a private exclusive temporary file, publishes by a no-clobber hard link, validates agreement with the published record, and syncs the directory. Existing corruption/conflict identifies the key and requires explicit invalidation. Pending extraction is deduplicated by key only after each caller has independently acquired authorized bytes. Complete membership observations use an exclusive temporary file and atomic rename. Across processes, the last complete observation may win; it does not replace live authority. Restart checks persisted record integrity and reconciles current source before use.

### Lines, trees, and structure

Text reads require strict UTF-8 and reject NUL-containing content as binary. Lines are one-based; CRLF, lone CR, and LF terminate a line, and a trailing terminator adds no phantom line. Empty content has zero lines. Whole, inclusive-range, and positive-tail shapes retain exact source text and original terminators. Ranges reject invalid endpoints; a tail longer than the file returns its actual whole range. Line records include original byte offsets and lengths. Continuation never splits a source line.

Tree views are roots, files, folders, or selected material. Requested depth omissions and output-cap truncation are separate facts. Trees contain root-qualified paths, selection flags, structural statuses, skipped reasons, counts, and the inventory digest.

Structure results use Swift artifacts and projections. Root-local posting lists normalize type names to NFC while retaining case. Breadth-first `uses`, `used_by`, and `both` expansion accepts depths 1–4, retains ambiguous candidate definitions and unresolved names, and terminates cycles. Relationship evidence identifies its direction and type name. Outcomes such as no symbols, unsupported extension, acquisition failure, oversize, and parse/decode failure remain explicit. These are approximate syntactic relationships, not compiler resolution.

### Search and output budgets

Search modes are `path`, `content`, and `both`. Literal/PCRE2 queries retain whitespace. MCP and Pi discovery-agent inputs default to literal content search with case-insensitive substring matching, empty filters, zero context, non-count-only output, and a null continuation. Glob queries default to path mode and use case-sensitive `path.posix.matchesGlob` semantics with neither text-query flag. Root, directory-prefix, include/exclude-glob, and extension filters run over admitted inventory paths before acquisition.

The configured ripgrep executable must support PCRE2 and have an audited build record. Path matching streams NUL-terminated relative paths, so embedded newlines remain path data. Content matching uses private ordinal-named files containing previously authorized bytes. Only CRLF and CR become LF in this search view; the BOM is retained. Ripgrep receives `--no-config`, `--encoding none`, explicit PCRE2/literal/case/word flags, and deterministic ordering. It never traverses source roots. Inputs are removed only after child settlement. A terminal summary must agree with the streamed match counts before results become usable; missing, malformed, or inconsistent records fail the search.

Search returns one complete grouped record per matched file, with original line numbers and terminators. Adjacent/overlapping context is merged by source line number. `occurrences` counts path and content match occurrences for the requested modes; each file also separates `pathOccurrences` from content `occurrences`. `matchingLines` counts distinct source lines with content matches, `matchedFiles` counts files matched by either mode, and `returnedMatchingLines` counts matching lines represented on this page. Count-only requests retain no snippets and return complete aggregate counts. Binary/undecodable content is reported in limitations. The adapter streams ripgrep output, retains one current file's context and a bounded page prefix, and continues counting after that prefix fills.

Continuations bind the complete query/filter/read shape, inventory digest, runtime generation, policy digest, relevant source identities, and ordered position. Changing those request facts rejects the token. Physical reads revalidate controlling policies and source bytes; continuations cannot substitute newer source. A response cap may change between pages because it does not change query identity.

`maxOutputBytes` measures the actual UTF-8 JSON serialization of the application result, including metadata and continuation. `pageResult` accepts a rendering callback so adapters can include their result representation in that measurement. Omitted complete records produce a continuation. A single oversized record produces `recordTooLarge` with its required size and remedy. If metadata or that diagnostic cannot fit, `outputBudgetTooSmall` returns only its code and required size; this control diagnostic is the cap exception. These caps are presentation limits, separate from any final export allowance.

## Drafts and material ownership

`WorkspaceHandle.createDraft(request, signal)` registers a freshness barrier and acquires required sources, documents, and patches before returning a `DraftRuntime`. Its request is cloned, validated against the closed `ContextBuildRequest` schema, and frozen. Task, constraints, purpose, required representations, documents, patches, discovery hints, allowance, and output name are immutable. A library draft object is its owner's capability; its printed ID is an inspection identifier rather than an independent authorization token.

Each draft retains a workspace operation lease. Physical preparation and finalization fork separately owned operations pinned to its inventory. Closing a public workspace handle leaves admitted draft work usable. Runtime closure rejects new admission, cancels draft preparation, joins finalization and operations, and then closes workspace and process owners. Exploration reads and selected-tree projections have no mutation access to the material store.

Source selection requests identify root-qualified paths. Admission resolves them against the pinned inventory, reads their exact bytes, and stores the raw identity and Git executable mode with the representation. `full`, `slices`, and `codemap` are mutually exclusive per root-qualified path. Upsert replaces the entire representation. Requested slice ranges and descriptions remain recorded; valid overlapping or adjacent ranges are normalized for rendering. Invalid endpoints and empty slice lists fail. Codemaps require a ready retained artifact, use its Swift projection, and retain its canonical key. Binary or undecodable source cannot become a Markdown representation.

Documents have distinct local and supplied variants. Local documents use the same root, inventory, and policy checks as source. Supplied documents retain complete strict-UTF-8 caller text and an asserted origin, which never authorizes a read. All documents and requested patches are immutable required material. A denied local request fails during acquisition. It is not converted to supplied text.

`update` prepares I/O before committing synchronously. Commit checks the submitted revision, cancellation, runtime/draft lifetime, editable state, and whether any finalization freeze occurred during preparation. A blocked manual finalization may reopen editing, but preparations that crossed that freeze remain invalid. Identical state-setting preserves the revision. Required source removal or representation changes fail with `requiredMaterialMutation`; stale revisions return `revisionConflict` and the current revision.

The mutation receipt contains the committed revision, changed-item costs, fixed overhead, known complete/incomplete measurement, allowance, remaining amount or excess, and unresolved diagnostics. The minimum receipt must fit before commit. Detail omissions are explicit and can be recovered through paginated cost inspection. `inspect` provides metadata, item costs, and material content. Metadata includes a handoff item with explicit `unset` state or the complete committed handoff in `set` state, including clarification, architecture, relationships and ambiguities. Material pages contain complete line records and a continuation bound to the material digest; metadata/cost pages bind draft identity and revision. A handoff record that exceeds the caller's output allowance returns the existing oversized-record diagnostic.

## Accounting and deterministic rendering

`utf8-21-over-80-v1` uses integer arithmetic: estimated units are `floor(21 × bytes / 80)`. The measured recipient file is the complete emitted `context.md`. The caller supplies either an acknowledged net allowance with overhead already reserved, or a verified settings record with explicit system/task/tools/history/output/delivery reserves. Unknown allowances remain unknown. `handoff.md` and `manifest.json` have integrity identities but consume no recipient allowance. The estimate is not an exact tokenizer result or provider acceptance guarantee.

`renderBundle` is pure and shared by mutation accounting, validation, finalization, and integrity verification. It orders materials independently of mutation order and measures complete headings, paragraphs, lists, fences, bodies, and final instructions. Each patch summary names its ID and root, comparison kind and scope, requested and resolved revisions, worktree paths, coverage and exclusions. Complete receipts, payload identities, per-path policy and target evidence are recorded in the manifest. Item estimates are individually rounded; total units are computed from the complete packet rather than by summing rounded item estimates. Missing handoff content makes measurement incomplete. Unknown or exceeded allowance and source-comparison mismatches produce blocking diagnostics, with complete cost information retained.

The packet orders advisory clarification, architecture/relationships/ambiguities, roots/comparisons, a tree of selected material, documents/evidence, full and sliced sources, codemaps, patches, and the final caller task/constraints. The discovery handoff uses Markdown paragraphs and lists. Root paths and comparisons have labeled entries, and the tree groups local paths beneath their root names. Each material heading identifies its path or supplied ID. Slice blocks identify their normalized line ranges and list the original range descriptions. Path and ID labels escape embedded control characters; material bodies retain their exact text. Material bodies and the original task/constraints are fenced, including marker-like text. Fences exceed every conflicting backtick run. Source bodies retain exact BOM/newline bytes; separators are outside their spans. Empty full-source bodies have zero-length spans. Every span records a UTF-8 byte offset, length, and digest.

The schema-version-1 manifest records request content/digest, historical inventory evidence, restrictions, handoff, all material records/spans, file identities, accounting, decoder identity, and verification checks. Hashes and policy inputs identify the sources. Runtime sequence numbers for inventories, draft revisions, timestamps, and random draft IDs are excluded from rendered artifacts.

## Patch acquisition and coherence

`suppliedPatch` records complete caller text, asserted origin, comparison identifiers, coverage, and target raw identities/modes. Its bytes and declared path authorization are verified. Source coherence requires usable matching target evidence for every selected source in the associated root. Integrity preservation does not prove an external producer's comparison completeness.

Local patch requests name a root that is the Git worktree root, an explicit commit or empty baseline, comparison kind, and all-paths or prefix-path scope. Commit references are resolved once to object IDs. Worktree targets come from confined live reads; staged targets come from captured stage-zero entries; commit targets come from endpoint trees. Repository/worktree identities, HEAD when present, applicable index facts, resolved endpoints, policy inputs, target byte/mode evidence, changed paths, exclusions, and the complete patch digest are recorded. Relevant executable mode is Git's owner-executable bit, represented as `100644` or `100755`.

Git processes use argument arrays, an explicit cwd, a restricted environment, literal pathspecs, no pager/replacement objects/lazy fetch, disabled optional locks and fsmonitor/hooks, and disabled external diff/textconv. Neutral scratch comparisons stop repository discovery above the private scratch tree. Each side is explicitly absent or a regular-file byte/mode value. Present pairs use `a/path` and `b/path` with `--no-prefix`; additions/deletions use the original path and `/dev/null` from the present side with explicit `a/` and `b/` prefixes. The fixed diff options include full-index binary output, three context lines, Myers, no renames, and no indent heuristic. Differing sides require exit 1, empty diagnostics, and nonempty patch output. An exit-1 missing-input error fails these requirements.

Participating authorized symlink/gitlink entries fail explicitly; entries outside the comparison scope or excluded by policy do not participate. Unmerged index entries fail during index decoding. Included untracked paths are enumerated through the confined policy reader, which also detects new comparison members during final checks. Staged/commit comparisons require all selected regular sources in the root, including supporting files outside a restricted patch scope, to match target bytes and mode. Unselected worktree dirt does not independently reject those comparisons. Final revalidation regenerates local patches against recorded endpoints and requires receipt and digest agreement.

## Finalization and verification

`finalize` freezes one revision and owns its publication claim. It reopens roots, revalidates every delivered local source/document and its controlling policy, verifies supplied material and comparisons, renders and measures the packet, writes fixed filenames exclusively, and checks complete readback. It repeats input checks immediately before claiming publication and asks the native bridge to publish and sync `manifest.json`. Ready returns the actual directory and manifest. A correctable manual validation failure returns blocked diagnostics and reopens editing with its lease retained; stale input, cancellation, or publication failure leaves the draft terminal and releases its workspace lease before the result settles, while inspection data and any candidate files remain available.

`cancelFinalization` returns `cancelling` before the claim and prevents publication. After the claim it returns `publicationInProgress`; the existing result promise and runtime closure join the ready/failed outcome. A claimed publication has its own non-aborted native request signal. Write/readback/sync failures never become ready. Partial files and uncertain publications remain available for explicit diagnosis, with no automatic overwrite or cleanup.

Worker closure or a malformed response after the publication claim returns `publicationUncertain` with sanitized worker-close facts. The candidate directory remains available for explicit integrity/current verification. An exclusive-create refusal remains a definite failure.

`verifyBundle(directory)` validates the saved manifest, file identities, spans, required representations, rendering, and accounting using bundle bytes only. It needs no runtime, native executable, search engine, Git, or model configuration. Integrity establishes internal consistency, not authentication of the bundle's author or filesystem authorization.

Both verifiers open each bundle component nonblocking, check that its descriptor names a regular file, and close the descriptor after reading or failure. A nonregular component returns `nonRegularBundleFile`. Current verification passes its combined caller/shutdown signal to descriptor reads and checks cancellation around acquisition and reading.

`verifyCurrentBundle(directory, runtime, signal)` first performs integrity/schema verification, then admits an internal verification operation. It never installs recorded inventory as current workspace membership, warms unrelated indexing, or publishes membership. The runtime validates the recorded declaration, combines recorded restrictions with current cache/output/credential denies, and reopens every source/output root against recorded aliases, canonical paths, and filesystem identities. Delivered local paths retain their original controlling-policy checks. Codemap revalidation compares each freshly returned native key with the recorded key. Comparison-scoped worktree enumeration remains necessary for live comparisons; unrelated directories are otherwise not enumerated. Admission, cancellation, operation closure, and runtime shutdown use the existing runtime and process owners. Neither verifier edits saved files or certifies continued freshness after its checks.

Current verification checks slice endpoints against the acquired source's actual line count and compares each saved body with the normalized slice from those bytes. Integrity decoding requires supplied-patch targets and coverage to match the frozen input, with a null repository receipt.

## Discovery and client ownership

`SmipRuntime.createClient(runner)` creates a client owner for public workspace/draft IDs and a `JobRegistry`. The runner is a transport-neutral capability receiving task facts, scoped tools, cancellation and progress. A null runner supports manual operations. Runtime closure closes its clients before the remaining workspace/process owners. Client closure rejects new work, cancels jobs and admitted manual operations, joins settlement, and releases workspace leases. Terminal manual finalization, whether ready, failed or cancelled, and terminal jobs release their draft leases while retaining inspection data; blocked drafts stay editable and leased.

Builder admission requires an available recipient allowance and a client-local request ID. The canonical digest includes the workspace handle and complete request. Duplicate input returns the existing job; conflicting input fails. Draft acquisition registers its freshness barrier and lease before admission returns. The runtime reconciles the workspace and acquires required material before discovery. The job transitions through discovery settlement and the existing draft finalizer; that finalizer owns the publication claim. Cancellation after the claim reports `publicationInProgress` and leaves the claimed operation to finish.

`context_builder_wait` observes one job for a caller-selected duration. Its cancellation and timeout leave the job running. Progress has monotonically increasing sequence numbers, and callbacks cannot change execution. Terminal snapshots remain retrievable until client closure. A blocked snapshot names an inspectable builder draft; public updates and finalization accept only caller-created manual drafts.

The Pi adapter launches one Node process through `ProcessSupervisor` for each run. Private LF-delimited JSON messages include generation/job identities. Closed schemas validate tool calls, evidence and terminal messages. The parent injects the pinned draft and operation, rejects unknown/retired generations and duplicate calls, and closes admission immediately on cancellation. Child closure alone cannot settle a pending parent tool. A terminal response received with outstanding parent work is rejected.

Worker retirement cancels the job's operation before joining pending parent tools, including its physical native reads and search processes. Shared indexing and other operation owners remain independent. Records received after retirement cannot alter the discovery receipt.

Pi discovery configuration requires an absolute `promptPath` and an `mcp` reference or `null`. At each run's start, the parent opens the prompt file nonblocking, checks the opened descriptor is regular, reads with the run's cancellation signal, and closes the descriptor. It decodes strict UTF-8, checks the `# smip discovery v1` LF-terminated marker, and records the raw-byte digest before starting a worker. The worker receives that retained text for its controlled resource loader and constructs in-memory session/settings. Editing the file changes later runs while active runs retain their admitted text. Its base tools are the four exploration tools plus draft inspect/update/validate. It selects one physical model and rejects thinking clamping. The adapter observes the existing shared stream function's result promise for both ordinary and summary calls; it does not consume the stream iterator again or implement recovery. Retry, provider, compaction and transport settings are explicit, and cache warming is off. The parent assembles the receipt from typed preflight, assistant, prompt, completion and lifecycle facts, retaining received evidence after forced worker closure.

`discovery.mcp` is `null` or `{ "agentDirectory": "/absolute/path" }`. The directory must exclude group/other permissions and contain a regular, strict-UTF-8 `mcp.json` file. Each job retains the configuration read at its start; edits apply to subsequent jobs. Only configured HTTP servers and exact selected tools are authorized.

The `mcpServers` object requires at least one server. Server names start with an ASCII letter and contain only ASCII letters, digits and underscores. URLs use HTTPS, or HTTP on `localhost`, `127.0.0.1` or `[::1]`, with no userinfo. Each server requires `exposure: "hidden"` and at least one exact tool name with `"direct"` exposure in `toolExposure`. Optional fields are `headers`, Pi's `oauth` settings, `description`, a positive per-request `timeout` in seconds, and `type: "http"`. Header values and `oauth.clientSecret` accept literal values and native escapes: `$$` for a dollar sign and `$!` for an exclamation mark. Commands and environment-variable interpolation in those fields are rejected. Tool selection authorizes names; server-side read-only credentials or scopes limit the server's privileges.

MCP OAuth state is stored in `mcp-auth.json` and server logging notifications in `mcp.log` under the private directory. CLI/MCP hosts exclude that directory and the declared/physical targets of `mcp.json` and `mcp-auth.json` from source access. Library hosts must include those paths in `credentialPaths`.

Configured discovery can call the selected MCP tools and the seven smip tools. A failed tool-availability check prevents the next model request and fails discovery with `mcpToolsUnavailable`. Interactive sign-in must precede jobs; the worker never opens a login browser. Source access, draft mutation, budget enforcement and publication remain subject to smip's workspace and draft contracts.

`DiscoveryReceipt.mcp` is `null` when MCP is disabled. Otherwise it records the admitted file's raw-byte `configSHA256`, authorized server/tool names and hashed endpoint URLs. Readiness `ready` records the first successful availability check, registered tool names in `tools` and a digest of their declarations in `declarationSHA256`; `unavailable` records a failed check. Shutdown `dispatched` means the shutdown event returned with no observed handler failure; `handlerFailed` records an observed handler failure. `notObserved` in either field means no corresponding observation was received.

`workerClosed` establishes local HTTP connection release. Readiness and shutdown observations do not certify remote cancellation, acknowledged session deletion or complete SDK cleanup. Successful discovery requires MCP readiness `ready` and shutdown `dispatched` whenever MCP is configured.

Success requires one accepted prompt, prompt resolution, `agent_settled`, idle completion, a latest normal-stop nonempty text/thinking-only assistant message, joined observations, disposal and child closure. The parent validates these receipt facts and settles its own tools before finalization. The final assistant acknowledgement is diagnostic evidence; the committed handoff remains the artifact authority. Recovered attempts stay recorded even if the SDK omits them from projected conversation state. Independent server identity can be unavailable, and local closure makes no claim about remote cancellation or billing.

Model registration consumes the validated configuration snapshot. Every locked credential read and write checks for executable configuration before key resolution or persistence. OAuth refresh uses Pi's serialized persistent credential storage. The credential adapter requires Pi 1.0.2 and the audited authentication module's exact source and declaration hashes; a mismatch fails with `unsupportedCredentialSDK`.

MCP hosts use the official 2.3.0 `serveStdio` factory and negotiation. Factories register handlers without storage or worker acquisition. The connection owns its client; stdin EOF joins application shutdown independently of transport closure. Shared TypeBox schemas feed `fromJsonSchema` and application validation. Each discovery runner supplies its result encoding to scoped tools for serialized cap measurement. Pi measures JSON text content and error metadata; MCP measures content, structuredContent and error flags. Error projection exposes stable codes, known revision/required-size fields and validated cache recovery targets. Failed or cancelled builder receipts carry the same validated `target`, or `null`, through library results, MCP `context_builder_result`/`context_builder_wait` and CLI `build` output. Cache corruption/conflict targets contain an explicit artifact or membership kind and a lowercase SHA-256 key. CLI recovery requires `cache invalidate --kind artifact|membership --key <sha256> --config <absolute-file>`; library recovery uses `runtime.artifacts.invalidate(key)` or `runtime.artifacts.invalidateMembership(key)`. Each invalidation removes only the named record. Exception messages and arbitrary details remain private.

The embedded dependency identity and terminal receipt use `buildLockSHA256` for the SHA-256 of the package-lock.json consumed by the build. Installed packages may resolve a different transitive graph; its lockfile and audit are separate deployment evidence.

MCP factory and stdio host `closed` promises resolve after successful cleanup or reject after cleanup failure. EOF, server-close and signal shutdown join application and transport cleanup. Cleanup continues after a failure, then the CLI reports a sanitized failure on stderr and exits nonzero; protocol stdout contains only MCP messages.

The stdio host forwards protocol bytes through a host-owned Writable to shared stdout. After application work and any claimed publication finish, shutdown cancels the wrapper's pending writes and joins their rejected send promises before completing transport cleanup. Expected output cancellation is separate from output or cleanup failure. The wrapper closes while shared stdout remains open for its owner. Bytes already accepted by stdout cannot be retracted, and local write settlement does not prove peer receipt.

The compiler uses strict NodeNext application checking with `skipLibCheck: true`. This exempts internals of third-party declaration files: Pi 1.0.2's generated model declarations omit JSON import attributes, and Google GenAI's declarations reference an optional legacy MCP type. Application checking retains `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` and `verbatimModuleSyntax`. Runtime integration tests exercise the actual pinned packages.
