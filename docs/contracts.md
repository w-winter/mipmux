# Native and workspace contracts

This document describes the private bridge implemented by `native/Sources/MipmuxBridge/`, its TypeScript schemas in `src/contracts/`, its client in `src/native/bridge-client.ts`, and the workspace/exploration APIs. Native directory capabilities authorize physical access. Workspace services apply exclusions and generation policy before requesting that access.

## Process and framing

Launch `MipmuxBridge <generation>` with an explicit environment. The client creates a fresh generation for each process and serializes requests. Each request is a closed object containing `wireVersion: 1`, a nonempty `requestId`, `generation`, and a discriminated `operation`. The TypeBox schemas and Swift parser reject unknown fields and malformed values. Base64 must round-trip to its canonical encoding. Only byte `0x0A` separates records; Unicode line separators remain data inside JSON strings.

Responses repeat the envelope identities. A request produces zero or more `bytes` or `entry` records followed by exactly one `terminal` record. Bytes use base64. A source response becomes usable only when its terminal receipt agrees with the accumulated byte count and SHA-256. A directory receipt covers the entry count and SHA-256 of the concatenated UTF-8 sequences `entryKind + NUL + name + NUL`, in emitted order. Directory entries are sorted by their raw UTF-8 names.

Malformed UTF-8, invalid frames, unknown versions, mismatched identities, duplicate terminals, unexpected record kinds, inconsistent receipts, and premature process closure fail the request and retire the client. Retirement rejects queued operations, invalidates handles, and joins process closure. A normal source failure returns a `failure` result and leaves the process available. `NativeFailure` exposes its code and optional errno. `NativeWorkerFailure` exposes the exit/signal/spawn receipt and the affected source identity when one was supplied.

## Operations

- `queryStructure` applies RPCE's graph traversal, output budgets, signature admission and reply formatting to an immutable root-local snapshot. It returns both the typed reply and rendered text. Headless root/file identities are stable SHA-256-derived UUIDs, used for the reference's ordering and equality checks.
- `renderFileTree` renders captured root/entry/selection data through RPCE's snapshot renderer. It supports full, folders, selected and automatic views, a scoped start directory, folder depth limits and legends. `onlyIncludeRootsWithSelectedFiles` controls selected-root filtering; full mode with an empty selection retains all roots. `showCodeMapMarkers` controls the plus markers and their legend. Callers supply each file's marker state for the presentation they are rendering. Exploration uses retained ready structure. The native adapter constructs temporary snapshot identities; these identities do not appear in the output or grant filesystem access. Relative displays use declared root aliases.
- `renderPromptAssembly` combines formatted section snippets through RPCE's `PromptAssemblyBuilder`. The caller supplies section order, disabled sections and the user-instruction duplication setting. Null and empty snippets are omitted; repeated sections in the order are emitted repeatedly. User instructions duplicated at the top are included even when their ordinary section is disabled. A nonempty snippet gets a terminating newline if it lacks one.
- `calculateTokenStats` applies RPCE's component calculation and DTO projection to captured raw prompt, fixed-constraint body, tree, Git and metadata inputs plus normalized full/slice/codemap token totals. Prompt duplication adds one copy of the raw prompt estimate. Optional zero components are omitted using the source DTO keys. The result describes the supplied component set; complete-packet measurement describes the final serialized context.
- `renderClipboard` packages captured file entries, codemap presentation, fixed constraints, a tree, Git text and literal user instructions. Entries identify ordinary files or authorized Git artifacts; authorization and acquisition occur before this boundary. Readable selected Git bodies take precedence over supplied Git text, including slices of sources. Codemaps and the optional tree form `file_map`; ordinary file blocks form `file_contents`. Caller flags control file inclusion, the user prompt, dates, ordering, disabled sections, duplication and optional titles. Fixed constraints use their dedicated section. File-block text uses the retained native formatter and slice assembler.
- `planClipboardPresentation` resolves captured copy settings through retained `PromptViewModel` methods and runs the retained presentation-intent planner against an admitted, pre-resolved catalog. It returns ordered requested file IDs, exact versus automatic intent, complete-root coverage and the accounting projection for ready maps. The adapter reuses source file models and the installed supported-language catalog. `resolveCompleteGitTarget` resolves the explicitly captured active root to its owning checkout through the existing native repository-layout and worktree identity owners.
- `projectGitArtifacts` projects a captured snapshot manifest, present-file paths and optional MAP bytes through RPCE's Git artifact policy. The caller supplies comparison display, mode, inline settings, automatic-selection aliases, worktree metadata and warning. The result contains the original reply fields, primary and advertised aliases, and ordered artifact records. Primary automatic-selection membership follows MAP then all-patch order; per-file jump indexes retain gaps and alias collisions. Inline `brief` selects snapshot metadata and the changed-file tree; other inline modes use the full MAP. Missing or invalid UTF-8 MAP bytes omit the inline object. Snapshot identity and unsafe artifact paths return `gitArtifactProjectionError` with the source diagnostic. Projection performs no filesystem access and grants no selection authority; callers must acquire its inputs through admitted capabilities.
- `decorateGitArtifacts` decorates captured per-repository artifact replies with primary aliases and readiness warnings, then aggregates successful diff totals while counting every repository result. Warnings are trimmed and joined in acquisition-then-readiness order. Repository acquisition errors remain separate results.
- `describe` returns the thirteen supported extensions, automatic source-decoder identifier, canonical bytes for each pipeline, parse limits, and regex configuration. `jitCapability` records compiled engine support; `jitExecution` records whether matching at startup used compiled JIT, was disabled, or found JIT unavailable under the automatic policy.
- `openRoots` admits existing absolute directories, resolving an explicitly declared root alias and returning its declared/canonical paths, device/inode, access kind, and generation-bound handle. Source and output capabilities have distinct access kinds. An optional expected identity supports reopening the same authority in another process; disagreement fails with `rootChanged`. Duplicate names or canonical paths in one declaration fail. Reopening an identity that the process already admitted with the same access kind returns that admitted capability after the fresh path and identity checks; it retains no additional descriptor, and a source capability is never returned for an output declaration or the reverse.
- `listDirectory` accepts a source handle and either `{ kind: "root" }` or `{ kind: "descendant", path }`. It emits each entry as file, directory, symlink, or other, then a complete receipt. Directory fingerprints must agree before and after enumeration.
- `walkDirectory` lists one directory of an inventory walk as `listDirectory` does, then returns each entry's ignore verdict: null for a symlink or other entry, otherwise whether the path is ignored and, for a directory, whether it is traversed and included. A walk begins with its root's request, which carries the root's captured ignore inputs; each later request names the same walk and comes after its parent directory's. The helper keeps the walk's compiled rules between requests and discards them when another walk begins. With hierarchical ignores, a descendant's request first captures and returns that directory's controls, as `captureIgnoreInputs` would.
- `readSource` accepts a source handle, relative path, and an expected raw identity or null. It emits exact bytes and returns their identity, the unchanged descriptor fingerprint, and the eligible canonical artifact key or null for an unsupported extension. Missing paths, denied access, special files, symlinks, and changed observations have distinct failures.
- `scanSearchSources` accepts ordered candidates, each a source handle, relative path and expected raw identity, with one literal or regex pattern and a shared result limit. It emits one outcome per candidate as soon as that file is scanned: skipped, a read failure, or the decoded text's identity with the scanner result and, for a matching file, its text. It then returns the number of outcomes. A skipped file is still read in full and checked against its expected identity.
- `extract` accepts an extension, exact base64 bytes, and the expected raw identity. It verifies that identity before decoding. It returns a retained core outcome, its canonical key, and, for ready artifacts, the original Swift API description and sorted defined type names. Unsupported extensions produce `unsupportedExtension` at the bridge level; they are not empty artifacts.
- `beginExport` creates one fresh, private run directory beneath an output handle and returns a run capability. `writeExport` exclusively writes `context.md` or `handoff.md`; `readExport` reads either file completely and returns its identity. `publishManifest` exclusively writes `manifest.json`, syncs the file and directories, and returns the written identity. The application finalizer owns material verification and the publication claim. A failure after manifest creation that leaves durability uncertain is `publicationUncertain`.

## File authority

Relative paths preserve filename spelling and Unicode. They reject absolute values, NUL, empty components, `.` and `..`. Root names are case-sensitive ASCII identifiers beginning with a letter and continuing with letters, digits, `_`, or `-`.

Directory traversal uses descriptor-relative opens with no-follow semantics. A fresh directory description avoids sharing enumeration offsets or filesystem caches between operations. Leaf reads use no-follow and nonblocking flags, then require a regular file through `fstat` before reading. Root aliases and directory identities are rechecked; export operations also recheck the run directory's identity. No descendant symlink is followed, and a source handle cannot authorize writes.

The source fingerprint records device, inode, size, POSIX mode, and modification/change times obtained from the opened descriptor. Device, inode, and timestamp seconds are decimal strings; nanoseconds, byte size, and mode are integers. Device identifiers retain the platform's signed representation. The bridge compares every field around acquisition and independently hashes the acquired bytes. Consumers use the captured mode for comparisons involving executable permissions. This establishes an observed byte sequence, not a filesystem transaction or future freshness guarantee. Application finalizers must reopen and check delivered material through the same authority.

## Decoding and extraction identity

`mipmux-strict-utf8-v1` accepts exactly the UTF-8 byte sequences that survive decoding and re-encoding unchanged. It preserves a leading BOM as U+FEFF, newline bytes, Unicode spelling, and empty input. Invalid sequences return `decodeFailed`; repaired text is rejected. Tree-sitter's internal UTF-16 offsets are distinct from raw UTF-8 byte identities.

The existing outcomes remain `ready`, `readyNoSymbols`, `oversize`, `decodeFailed`, and `parseFailed`. Oversize reasons distinguish UTF-8 bytes, UTF-16 units, and lines. Grammar/query exceptions are operation failures, and a crash is a worker failure.

Swift constructs the sole canonical artifact key. Pipeline domain `codemap-pipeline-identity-v2` includes the required regex-engine fingerprint along with the retained decoder, grammar/query, version, flag, and limit fields. The fingerprint hashes sorted-key JSON under `mipmux-regex-engine-v1`, including the pinned PCRE2/SLJIT source identities, patch set, Unicode version, width, recipe settings, and resolved JIT policy/support/execution facts. Platform, compiler, and hashes of library artifacts are separate build evidence. The client validates the canonical bytes' digest rather than reimplementing their encoding.

## Ownership and cancellation

`ProcessSupervisor` owns each child from spawn through the `close` event. Callers provide executable, argument array, working directory, environment, and the supervisor's `terminationGraceMs`. It sends SIGTERM on stop, escalates to SIGKILL after that grace, and awaits closure of the process and its streams. Its JSON diagnostics contain opaque process identities and exit/signal facts, not command arguments or stderr bodies.

Each `BridgeClient` owns one serialized native child. Aborting a request retires that client and rejects its queued work; closing one client leaves other clients under the supervisor running. Shared indexing must have its own owner: cancellation of a waiter releases its interest rather than aborting another owner's bridge. Supervisor closure stops admission and joins every owned child. A failed operation is never automatically replayed.

## Workspace generations and exploration

`MipmuxRuntime.declare(spec, signal)` admits named source roots and the output-root identity before warming. `WorkspaceSpec` requires ordered roots, explicit prefix/glob exclusions, and an absolute existing output directory. Names and canonical root paths are unique. The declaration key includes source/output identities, exclusions, state-directory exclusions, configured ignore settings, and the ignore implementation version. Each generation's policy identity records repository authority, effective settings and captured control files.

Every permitted directory is listed through the bridge. The native ignore reader accepts an admitted source-root capability and the fixed control names `.gitignore`, `.repo_ignore` and `.cursorignore`. For Git roots it resolves the containing repository, Git directory and common directory, then captures controls from the repository root through the loaded subroot. Policy inputs contain absolute logical paths and exact text/raw identity, explicit absence, or a diagnostic for an unavailable optional nested control. Mandatory Git controls require strict UTF-8, regular files, no leaf symlink and at most 4 MiB. Secondary controls use resolved metadata paths; protected paths remain denied. Invalid required controls prevent complete enumeration.

Parent rules precede descendant rules. The original hierarchical evaluator locks ignored prefixes to their controlling rules and acquires deeper controls only when its evaluation requests them. Ordinary directory crawling follows the original negation traversal hints. Explicit exclusions apply through every containing canonical root. Absolute denies match canonical source paths and equivalent paths through every containing admitted root's declared alias. Configured protected paths retain their declared spellings and include their existing canonical targets, including independently declared aliases. An absent optional credential file is denied at its declared path and at the physical path formed from its canonical existing ancestor plus the absent plain-name remainder, so creating it later beneath an independently symlinked parent cannot admit it. A dangling symlink or a remainder containing `.` or `..` components fails admission with `credentialPathUnresolvable`; current verification applies the same rule. No descendant source symlink is followed.

`refresh(signal)` registers its barrier before waiting and returns the immutable publication satisfying that barrier. One owner serializes scans and coalesces later requests into a follow-up scan. A later scan's failure affects only observers still waiting for publication. A scan decides admission for all of a directory's entries with one ignore query per root. It reads and hashes each permitted regular file unless the file's listed descriptor fingerprint (device, inode, size, mode, and modification and status-change times) equals the one recorded when an earlier scan read it and its codemap record is still cached; such a file keeps its earlier entry, as RPCE's content cache trusts an unchanged file fingerprint. A file whose status-change time is within two seconds of the start of its read is read again by the next scan, because file systems that round times can leave an in-place rewrite of the same size with an unchanged fingerprint. A scan saves these fingerprints and entries when they differ from the saved ones, so the first scan after a restart reuses them as well. Saved entries apply only while the executable the native helper started from, its description and the codemap setting are the ones that produced them; otherwise the scan reads every file. The immutable snapshot separates enumeration completeness, settled processing, per-file structural outcomes/acquisition failures, and skipped-entry reasons. `inventoryDigest` describes content and policy; `generation` orders observations within the owner. An incomplete enumeration cannot admit an exploration operation. After native generation retirement, a later explicit refresh joins that generation's closure and reopens source and output roots against their original declared/canonical paths and device/inode identities. Failed requests remain failed.

Workspace handles and operations hold separate leases. Closing a handle prevents further calls through that handle and releases its lease. It does not revoke another handle or an already admitted operation. A closed handle keeps no reference to its workspace. When a workspace's last lease is released, the workspace closes, and the native helper that writes Git snapshots to its output root stops unless another open workspace shares that output root; the next snapshot write starts a new helper. Shared extraction retains its producing owner until the extraction settles. A consumer's cancellation releases its observation of another owner's extraction. Cancelling a refresh observer releases that observer without aborting the shared scan. Runtime shutdown aborts inventory owners before joining clients, then joins native work, pending admission and operation lanes.

Scoped source reads admit only the roots needed for that access and its overlapping-root policy. Each native read rechecks its retained capability against the physical root. An unavailable independent root does not prevent reading a healthy root. Selection views report unavailable represented roots in automatic and manual modes while retaining healthy results. Automatic graph queries skip unavailable roots before consuming shared query budgets. Git diff acquisition validates the declared roots associated with its selected paths and checkout identities. Other Git operations, tree and structure serving validate all source roots. Packet publication and current verification check each root against its recorded availability state and validate the output-root identity.

`openOperation(signal)` pins the latest published inventory and policy, including incomplete enumeration. It waits for initial publication when none exists; an unfinished later refresh does not delay capture of an existing publication. Known-source exploration remains available; structural replies identify incomplete coverage. Draft admission requires complete enumeration and returns `enumerationIncomplete` otherwise. The first native tree/structure query or physical read lazily opens an operation-owned bridge against the originally admitted root identities. Operation closure aborts its physical work and waits for all admitted calls and owned child closure. Selected-tree requests consume a caller-supplied immutable `{ draftId, revision, sources }` projection; the draft owner is responsible for supplying authorized selection data.

### Persistent artifacts

Artifacts reside at `v1/artifacts/<shard>/<keyDigest>.json`. The closed record schema contains `schemaVersion: 1`, Swift-produced `keyCanonicalBase64`, `keyDigest`, `outcome`, `projection` only for ready outcomes, and `recordSHA256`. The checksum covers recursively key-sorted JSON of every other field. Array order is retained. Reuse validates the schema, canonical base64/key hash, correspondence to the current Swift key, checksum, and projection/outcome agreement.

Insertion writes and syncs a private exclusive temporary file, publishes by a no-clobber hard link, validates agreement with the published record, and syncs the directory. Existing corruption/conflict identifies the key and requires explicit invalidation. Pending extraction is deduplicated by key only after each caller has independently acquired authorized bytes. Workspace cache keys include the inventory schema version. Inventory snapshots are held in memory only; a restarted server scans its roots again. Each workspace's `reuse.json` holds the fingerprints and entries a scan after a restart may reuse, without codemap records. Its closed schema contains `schemaVersion: 1`, `workspaceKey`, a `binding` digest of the native executable identity, native description and codemap setting, `files`, and a `recordSHA256` over the other fields. A scan whose reusable files differ from the saved ones replaces it through a temporary file and atomic rename; across processes, the last complete record wins. A corrupt record fails the scan with target kind `reuse` until it is invalidated.

### Lines, trees, and structure

Source acquisition tries UTF-8 first, then RPCE's retained character-encoding detector. macOS uses Foundation's heuristic when the detector cannot identify an encoding. Linux converts detector-selected encodings with its native codec and returns `decodeFailed` when detection or conversion fails. Some short Big5 and GB18030 files accepted by the macOS heuristic are undecodable on Linux. Lines are one-based; CRLF, lone CR, and LF terminate a line, and a trailing terminator adds no phantom line. Empty content has zero lines. `start_line` is one-based and defaults to 1. A positive start with `limit` reads at most that many lines; omitted or negative limits read the remainder, and zero returns no lines. A negative start reads the last N lines and rejects any supplied limit. Zero start is an error; starts beyond EOF return empty content and the source diagnostic. `offset` is the current start alias. Numeric strings use RPCE argument priority: integer start, integer offset, string start, then string offset. Returned content retains original terminators. Line records include byte offsets and lengths in the decoded UTF-8 representation. Continuation never splits a source line.

Tree requests use `type: roots` or `type: files`. File modes are auto, full, folders and selected, with optional root/directory scope and folder depth. The native RPCE renderer supplies tree text; stars identify selected implementation and pluses identify available code maps. Skipped entries are omitted. Response pages retain complete rendered lines, with the inventory digest and a continuation.

Structure queries use the retained RPCE seed-resolution, traversal, policy, DTO assembly and text formatter. Omitted seeds use the captured authorized full/sliced selection. Explicit input accepts 1–256 root-qualified file/directory selectors; a directory reference can identify a whole root. Direct files are resolved before explicit directories. Folder expansion visits captured child files before child folders, deduplicates physical paths and retains the first limit-exceeding file after 8192 unique candidates. The resulting seed metadata and graph truncation remain separate. Missing inputs are skipped; a request with no resolved files returns the source `path_not_found` reply. Names preserve case, normalize to NFC and match within one root. Breadth-first `uses`, `used_by` and `both` expansion accepts depths 1–4. Edges retain source-to-definition orientation even during reverse traversal; cycles, self-edges and each source's unresolved references remain in structured evidence. Names with more than 4096 definition candidates produce `too_common` instead of edges.

`size` selects small (40 nodes, 4000 edges, 32000 graph bytes), medium (120 nodes, 10000 edges, 96000 graph bytes) or large (200 nodes, 10000 edges, 400000 graph bytes). Roots share the remaining budgets in UUID order. Traversal checks the source's 10000ms per-root deadline. With `signatures: true`, whole signature texts share 1500, 4500 or 18750 estimated units respectively; oversized signatures are omitted with a diagnostic while later smaller texts can fit. `summary.tokens` charges admitted signature text and separators.

A ready-no-symbols artifact contributes a covered node with no definitions. Unsupported extensions have no graph slot and produce not-indexed seeds. Failed acquisition of a supported admitted file produces a pending seed; decode/parse failures and oversize artifacts produce terminal, not-indexed seeds. A supported candidate that becomes non-regular is terminal-excluded. Supported and classified counts include terminal-excluded candidates; pending candidates count only as supported. Incomplete enumeration remains indexing and unresolved names become `not_indexed_yet`. Traversal and signature limits produce partial replies with source diagnostics. Resident admission separately limits each root to 100000 nodes, 2000000 postings, 1000000 edges and 192 MiB of logical retained storage. A resident rejection returns `graph_revoked` with no graph evidence from that root. Structured output retains evidence that the source's text formatter omits, including unresolved records and self-edges.

The complete encoded reply, including native text and structured data, must fit `maxOutputBytes`; otherwise the result is `outputBudgetTooSmall` with its required size. Structure replies have no continuation.

### Read-only Git

`git` accepts `op: status`, `op: log`, `op: show`, `op: blame` or `op: diff`. Read operations use ordered `repositories: [{ root, path?, worktree? }]` selectors. Each names a declared root, an optional root-relative nested-repository path and an optional absolute advertised same-repository worktree. Checkout paths are deduplicated case-insensitively, retaining the first selector. Omitted or null selectors on a workspace operation resolve the first declared root with a checkout; repository absence is skipped, while authorization, identity, protocol and cancellation failures propagate. Draft-owned implicit reads revalidate all initially elected checkouts. Status uses all elected checkouts; implicit log/show/blame with multiple checkouts returns `gitExplicitRepositoryRequired`. An unavailable or deferred initial target requires explicit selectors. Diff uses its separate `root` and `worktree` fields.

Status returns branch/upstream and ahead/behind metadata when present, sorted staged/modified/untracked path sets, and a summary from one coherent porcelain-v2 observation. Status paths are relative to the owning checkout, including when the declared root is a subdirectory. Multiple checkouts produce ordered `repos` rows containing status/worktree metadata or an expected Git-query/status diagnostic; security, identity and cancellation failures abort the request. Log/show/blame use the first selected checkout and include a warning when multiple were selected. Linked-worktree replies include the retained native worktree DTO and warning. Every selected checkout is revalidated before the reply is served.

Log defaults to ten commits and no path restriction. Operation-level log/blame `path` is relative to the declared root for a plain selector, or checkout-relative when the selector supplies `path` or `worktree`. Blame requires a file path and accepts `lines` in `start-end` form. A valid ordered pair restricts the range; absent, malformed or reversed text selects the whole file, matching RPCE's argument handling. Log replies retain commit IDs, authors, ISO dates, subjects and file/insertion/deletion totals. Blame replies retain line numbers, abbreviated IDs, authors, ISO dates and content.

`show` requires a nonempty `ref`, resolves it to a commit and returns its full message and file/insertion/deletion totals. `detail` defaults to `"summary"`; `"files"` includes file statistics, and `"full"` includes complete hunks. `"patches"` maps to `"full"`, and detail matching is case-insensitive. `contextLines` defaults to three and `detectRenames` to false. Show uses Git's `<commit>^!` diff semantics. For a root commit, that expression compares the commit with captured live worktree bytes. Show and diff apply host denies to both rename/copy endpoints before acquiring returned bodies. Omitted paths are listed in `exclusions`; totals describe permitted evidence. Missing binary counts and empty hunk lists are omitted from the result. Invalid metadata returns `gitShowMalformed` with the source diagnostic before any diff command runs.

`diff` defaults to `compare: "uncommitted"` and `detail: "summary"`. Comparisons include `uncommitted:<base>`, `staged`, `staged:<base>`, `unstaged`, `mergebase:<base>`, `uncommitted-mergebase:<base>`, `staged-mergebase:<base>`, `back:N` and Git revision specifications. `main` and `trunk`, including staged/uncommitted prefixes, resolve the repository's main reference with merge-base semantics. Detail can be summary, files, patches or full; exactly one collected path upgrades summary to patches. Patches use RPCE's 300-line allowance; full retains complete hunks. `contextLines` defaults to three and `detectRenames` to false. Worktree and unstaged comparisons include untracked files; staged and revision comparisons exclude them. Results retain source totals, status counts, paths and hunk fields.

An owned draft can request `artifacts: true` on `git` diff to publish repo-scoped snapshots and append their readable MAP and optional whole patch to mutable selection. MCP callers supply the owning `draftId` alongside `workspaceId`; scout calls already carry that ownership. Publication defaults are `mode: standard`, `scope: all`, an automatic snapshot ID, and `inline: { map: true, mode: brief, max_lines: 120 }`. Mode and scope are case-insensitive. `snapshot_id` is trimmed; blank, `auto` and invalid overrides request an automatic ID. Inline line count is at least one. Only verified newly added primary aliases appear in `auto_selected`; existing full files, slices, manual codemaps and automatic mode retain their selection state. Per-file patches are advertised for explicit selection.

Scout publication writes files, CURRENT and retention before catalog registration and primary selection. It then decorates and encodes the reply, checks its complete response size, and installs exact insertion grants. A failed or cancelled reply retains completed files and committed selection but installs no new grant. Expected primary-commit failures add readiness warnings and omit `auto_selected`. Expected grant-authorization failures invalidate the grant, log the failure and return the encoded publication reply. Cancellation propagates through both stages. `manage_selection` get reports committed state after a missing or failed reply.

Before installing a grant, the draft authorizes every advertised candidate, including unselected per-file patches, against current catalog, manifest, root and checkout authority. The draft revision and freeze generation are checked again after those reads. A failed candidate revokes the complete grant, including the prior publication's aliases; completed files and selection remain available under their own access rules.

Diff `path` and `paths` are collected in that order. Relative inputs are checkout-relative Git pathspecs, including glob/magic/exclusion syntax. Absolute inputs under the checkout are literal paths. An explicitly scoped request whose paths normalize to an empty set produces an empty diff. A declared subroot admits read-only evidence from its owning checkout. Optional `worktree` names an advertised checkout of the same repository. Access requires loaded-root admission and matching checkout/shared-Git-directory identities, checked again before replying. Credential paths and explicit workspace exclusions remain denied. Both rename/copy endpoints must be permitted; omitted endpoints appear in `exclusions`. Ordinary workspace reads and selections remain scoped to declared roots.

`compare: "last"` reads the owning checkout's repo-scoped `CURRENT` and manifest, then compares the live worktree against the saved fingerprint's HEAD. A normalized named snapshot uses the same rule and takes precedence over a Git ref of the same name. `main` and `trunk` resolve the main reference before checking for a named snapshot. A missing date/minute-shaped snapshot ID produces `gitSnapshotNotFound`; a custom name with no readable manifest is parsed as an ordinary comparison. Missing CURRENT and unreadable CURRENT manifests return `gitSnapshotUnavailable` and `gitSnapshotManifestUnavailable` with RPCE's diagnostic text. These comparisons acquire fresh permitted diff bodies from Git; the saved manifest supplies the base HEAD.

During discovery, a scout can omit `root` from a diff request when its initial full-file or sliced selection elects a Git checkout. Each selected file resolves to its nearest checkout, including nested repositories. The checkout group requires one most-specific declared root containing all its selected files. Targets sort by root name, checkout key, repository ID and worktree ID; the primary target is the first sorted checkout containing the first selected full-file path, or the first slice path when no full files are selected. Election is deferred when the initial selection is empty or contains only codemaps. Mixed Git/non-Git ownership or ambiguous roots refuse implicit reads with `gitTargetRequired`. Standalone workspace Git calls require an explicit root.

Before each implicit diff, discovery revalidates every initially elected checkout, including checkouts removed from the current selection. Repository IDs identify the shared Git directory; linked worktree IDs also identify their per-worktree Git directory. A changed checkout layout or identity returns `gitRepositoryChanged`. Explicit root-scoped reads remain available when initial election is deferred or unavailable.

Ownership of selected files follows the nearest repository marker. An available `jj` executable gives `.jj` precedence over `.git` in the same directory; a nearer Git checkout retains its own ownership. Executable discovery searches the native process's `PATH`, then `/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin` and `~/.cargo/bin`. Initial Git target election requires Git ownership. Automatic Review reports Jujutsu paths as `unsupportedBackend` and retains diffs from healthy Git checkouts.

VCS ownership caches successful lookups by selected path and checkout root for the runtime lifetime. An uncached path can update the cached backend for its checkout root; previously cached selected paths retain their own results. Missing repositories are queried again. Jujutsu availability is cached after its first check. Checkout revalidation checks the cached backend and freshly reads Git layout and identities. Cancelling a caller ends its wait while the shared lookup completes; closing the runtime releases the resolver. Recreate the runtime to clear these caches.

Draft-owned publication capture requires an initially available target. Admission captures the ordinary full/sliced selection once, requires a nonempty checkout set within the original identities, and revalidates both sets. A changed checkout set or empty admitted selection returns `gitSelectionOwnershipChanged`; an explicit requested checkout outside the frozen target returns `gitPublicationTargetDenied`. Acquisition stops on cancellation or a change in freeze generation; ordinary selection edits can proceed. Selected-scope acquisition uses the captured paths. Files may be added within an elected checkout; admission constrains ownership rather than the original filenames.

Primary Git publication merges the captured selection with the latest committed selection through RPCE's native merge function. Captured paths precede new latest paths, captured slices win collisions, and automatic mode requires both inputs to enable it. Primary MAP and whole-patch paths are appended while retaining manual-codemap membership. If another edit commits during native projection or acquisition, preparation repeats against the newer revision before the single selection commit. Snapshot publication is not repeated. The reply reports newly added primary aliases; a merge that changes only dormant membership still advances selection revision. Latest prompt and supplied-document state remain authoritative. Advertisement installation retains its separate committed-revision and ownership checks after reply admission.

`DraftRuntime.publishGitSnapshot` writes an admitted captured comparison through the owner of mutations to its output directory. It resolves a snapshot ID before fetching a commit graph with at most 20 entries. It preserves quick/standard/deep snapshot bodies, records the creating draft UUID, writes CURRENT and runs count retention. Artifact projection uses confined reads of the saved MAP and optional artifact paths. After catalog registration and ownership checks, the method replaces the draft's exact readable-alias grants and returns written-file bytes, checkout identity and artifact projection. Selection membership is a separate operation. The byte limit on diff replies governs presentation rather than the saved evidence. A failed write or CURRENT update retains the completed files; later lifecycle, ownership and cancellation failures also retain completed filesystem effects. Opened snapshot handles are released.

### Search and output budgets

Search modes are `auto` (default), `path`, `content`, and `both`. The native RPCE rules choose content for recognizable regex patterns, paths for path/wildcard patterns, and both for short or identifier-like terms. MCP and Pi discovery-agent inputs default to case-insensitive matching, empty filters, zero context, non-count-only output, and a null continuation. Text patterns are trimmed using Foundation whitespace and newline rules; an empty trimmed pattern returns `invalidSearchPattern` with a diagnostic. Omitted `query.kind` uses `auto`, which detects regex syntax through RPCE's native helper. Explicit `literal` and `regex` kinds select the interpretation directly. In literal content searches, each space matches one or more whitespace characters, with punctuation escaped and `wholeWord` ignored for that branch. Other content queries apply `wholeWord` with PCRE2 `\b` boundaries. Literals are escaped before wrapping; regex grouping comes from the supplied pattern, so `left|right` becomes `\bleft|right\b`. Path searches ignore the whole-word flag.

Content patterns have a 2,000-character limit measured in Swift extended grapheme clusters. Admission checks the trimmed literal or regex before flexible-space conversion or whole-word wrapping. Regexes also pass RPCE's group-count and high-risk checks. Rejected content-only queries return `invalidSearchPattern` with the native diagnostic. In `both` mode, a content-admission failure leaves the path results available. Path-only queries use their path-matching rules.

Glob queries select path mode and default to case-insensitive matching; `query.caseSensitive` controls case matching for every query kind. Native wildmatch applies RPCE's any-depth and suffix-expanded glob candidates, so `*.swift` can match `src/Foo.swift.more`. Use an anchored regex for an exact suffix. Path candidates are standardized relative paths and root-alias-prefixed paths. Each file contributes at most one path hit. Path hits are limited in physical full-path UTF-8 order; content results follow native Swift path ordering. Native extension and exclusion filters apply before content acquisition and before either stage's result limit.

`filters.roots` narrows declared roots. `filters.paths` accepts raw file/folder paths, root aliases, absolute paths and wildcards as an OR scope. Exact matches use the native catalog and path locator; missing paths use the source prefix clause. Absolute wildcards bind to their longest owning root. Ambiguous input returns the source diagnostic when no usable clause remains.

Each new search reconciles catalog membership through the workspace refresh owner, then pins a query operation. Reconciliation lists the whole declared workspace, including files outside the query scope, and rereads only the files that the refresh rules above do not let it reuse. Raw scopes are parsed before reconciliation and exact clauses are refreshed afterward. A continuation uses the current generation without starting another reconciliation. Its token is rejected if another refresh or new search has advanced that generation. Query operations close after their reply or failure settles.

Path regex compilation tries the supplied pattern, compressed doubled escapes before metacharacters, and RPCE's normalized pattern in that order. If compilation still fails, path matching applies glob or literal-substring rules to the original pattern. Path compilation keeps anchors bound to the complete candidate path, including paths containing newlines.

Content regexes use RPCE's compile-repair sequence before content scanning. A repaired compilation returns the source `warning` text with the results, including zero-match results. In `both` mode, a content-compilation failure leaves path results available.

Recognized pattern failures return a search result with zero counts, an `error` containing the issue, an optional `suggestion`, and MCP `isError: false`. Empty queries and complexity rejections are tool failures. In `both` mode, a healthy phase supplies results even when it has no hits; if both phases fail, the content failure determines the result. `pathError` and `contentError` identify failed phases in partial results. `perFileErrors` records scanner failures by `root` and `path`; other files can still match. Pattern diagnostics use `{ kind: "pattern", issue, suggestion }`; `suggestion` contains text or null. Rejections use `{ kind: "rejected", message }`. Native transport, authorization and cancellation failures propagate as tool failures.

After a complete content pass finds zero matches, literal queries can retry with unnecessary metacharacter escapes removed. Regex queries try compressed double escapes, a normalized pattern, then literal quoting, in that order. Every retry searches the same filtered candidate set. A content match in any file keeps the results of the first pass for all files. Successful recovery returns the source `warning`; compilation warnings remain present even if later passes find no matches. Count-only searches use aggregate content counts for the same decisions.

`filters.extensions` accepts exact dotted extensions such as `.swift` and `.SWIFT`; `.` selects files with no extension. Exclusions without `*` or `?` are case-insensitive substrings of the relative path. Empty exclusions leave all files eligible. Other exclusions use native wildmatch: `*` can cross directory separators, and `**` enables globstar behavior. An exclusion such as `[ab].swift` is literal because it contains neither `*` nor `?`. These filter rules are independent of `query.caseSensitive`.

`maxResults` defaults to 50 and independently limits path hits and matching lines within file contents. Nonpositive values collect no hits. Collected replies share a 48,000-character display allowance, charged to content matches before path matches. Each charge includes the root-qualified path, the matching line's number and text, and framing; context lines do not consume this allowance. `sizeLimitHit`, `omittedContentMatches` and `omittedPathMatches` identify results excluded by that allowance. `limitHit` indicates either a collected stage reaching its query limit or the matches exceeding the display allowance. Count-only requests scan all matching lines within file contents while retaining the path limit; they bypass display clipping and set `limitHit` to false. Response-size pagination operates on the retained result set, so following a continuation does not raise either limit or expose omitted results.

Native path matching receives captured path metadata, including embedded newlines. Plain literal content uses Foundation comparison, including canonical Unicode equivalence and Unicode case folding for case-insensitive queries. Raw regex queries use the native RPCE scanner over original decoded text. Anchored or expensive greedy-dot patterns use line scanning, as do buffers above 1,000,000 UTF-8 bytes; ordinary regexes use full-buffer scanning. Full-buffer results project nonempty matches onto their start line and count each start line once. Generic PCRE2 line scanning tests complete CR/LF-delimited lines and applies the source's 64 KiB line limit. Specialized source plans keep their own scan policies. Native preparation rejects excessive pattern complexity before scanning.

Flexible-space and whole-word literals execute RPCE's native line-scanning branches over original decoded text, including embedded NUL bytes. Flexible spaces use the source PCRE2 converter and line policy. Whole-word literals use the source ASCII plan or PCRE2 boundary expression. Count-only requests use the source count-only branches; collected results retain one hit per matching line. The `engine` field identifies the content strategy, or `RPCE path` for path-only queries.

Search returns one complete grouped record per retained file, with original line numbers and terminators. Adjacent/overlapping context is merged by source line number. `matchingLines` counts retained content matches, `pathMatches` counts retained path hits, and `totalMatches` is their sum. `totalFiles` counts files with retained content matches; count-only requests use the number of files with matching content. `matchedFiles` counts distinct paths represented by content rows or path hits before display clipping. Count-only replies contain no content rows, so their `matchedFiles` counts only path hits. `pathMatchLines` lists retained root-qualified path hits, sorted in count-only replies. `returnedMatchingLines` counts matching lines represented on this page. Each file reports its `matchingLines` and whether it retains a path hit. Collected replies include `perFileTotals` for every file with content matches within the query limit, including files omitted by the display allowance. Count-only requests retain no snippets and return all content totals plus the limited path-hit count. Query-limited matches are collected before display clipping and byte pagination.

`scopedFileCount` counts admitted scope records before extension/exclusion filters. A path filter that admits zero files produces a `suggestion` to inspect the file tree. Successful replies include `searchedFiles`, the candidate count after extension/exclusion filtering, regardless of hit counts or display limits. `enumeration` reports the reconciled inventory's coverage. `unavailableRoots` identifies physical roots excluded after identity checks; a replacement at the same path remains unauthorized. A content pass reads, decodes and scans all available candidates in one native `scanSearchSources` request. The client checks each returned file text against its identity and keeps only the lines that the file's search record shows. As in RPCE's validated content read, it skips a file whose first 8,192 bytes contain a NUL byte or more than 30% control characters, unless its extension or name is always text; it also skips undecodable files. Skipped files are not reported. New content searches retain healthy results when a file, or a directory containing it, becomes unavailable after reconciliation, and report each affected path in `limitations`. Continuations require their captured source identities, including for the files they skip. Managed registrations remain owned when their physical root is unavailable; required material and publication checks use their captured identities.

Continuations bind the complete query/filter/read arguments, inventory digest, runtime generation, policy digest, relevant source identities, and ordered position. Changing those request facts rejects the token. A new search uses the controlling policies that its reconciliation captured. A continuation revalidates every candidate's controlling policies, querying each root once for all candidates, including on path-only pages, which read no file contents. Content reads check source bytes against the captured identities, so continuations cannot substitute newer source. A response cap may change between pages because it does not change query identity.

`maxOutputBytes` measures the actual UTF-8 JSON serialization of the application result, including metadata and continuation. `pageResult` accepts a rendering callback so adapters can include their result representation in that measurement. Omitted complete records produce a continuation. A single oversized record produces `recordTooLarge` with its required size and remedy. If metadata or that diagnostic cannot fit, `outputBudgetTooSmall` returns only its code and required size; this control diagnostic is the cap exception. These caps are presentation limits, separate from any final export allowance.

## Drafts and material ownership

`WorkspaceHandle.createDraft(request, signal)` registers a freshness barrier and acquires required sources, documents, and patches before returning a `DraftRuntime`. Its public request is cloned and validated against the closed `ContextBuildRequest` schema before the freshness barrier. Native preset resolution binds the runtime copy context into a frozen `CapturedContextBuildRequest`. Task, constraints, copy preset, stored prompt catalog, prompt duplication, purpose, required representations, documents, patches, discovery hints, allowance, and output name are immutable. A library draft object is its owner's capability; its printed ID is an inspection identifier rather than an independent authorization token.

Each draft retains a lease on its workspace operation. Tool invocations, selection preparation and finalization capture separately owned operations from the current published catalog, under the original root identities. Acquisition, automatic graph resolution and rendering within one preparation use that operation's inventory. Captured material bodies and required source identities remain fixed; publication revalidates them against physical sources. Explicit workspace registrations provide additional captured records. Terminal inspection uses the inventory captured by finalization. Closing a public workspace handle leaves admitted draft work usable. Runtime closure rejects new admission, cancels draft preparation, joins finalization and operations, and then closes workspace and process owners. Exploration reads and selected-tree projections have no mutation access to the material store.

The draft owns one canonical selection: selected paths, manual-codemap paths, slices and automatic mode. Acquired materials are its effective presentation, not a replacement for that membership. Full or sliced content takes display priority when a path also has manual-codemap membership; removing the full selection exposes the retained manual codemap. Prompt/document edits and source edits for other paths retain dormant memberships. Explicit representation replacement through `draft_update` changes that path's representation, while source clearing restores the required baseline.

Explicit context disposal owns Git snapshot cleanup. `ClientRuntime.disposeDraft(draftId, signal)` and MCP `draft_dispose` close a manual draft, join its admitted work, run snapshot maintenance for its draft UUID, and forget the client's draft capability. `ClientRuntime.disposeJob(jobId, signal)` and MCP `context_builder_dispose` cancel discovery or join an in-progress publication before disposing the job's draft. Jobs retain their terminal receipt and request-ID deduplication; a repeated job disposal returns zero after its draft is released. Disposal belongs to the connected client and is excluded from the tools available to the scout.

Cleanup scans current manifests and removes snapshots whose owner UUID matches the disposed draft. A snapshot overwritten by another context belongs to its latest manifest owner. Maintenance updates affected CURRENT pointers, cleans empty directories and invalidates its retention index. `deletedSnapshots` counts successful removals; unreadable manifests and unsuccessful individual deletions are skipped according to RPCE's maintenance policy. Saved packet files remain available for integrity verification. Normal finalization, workspace closure, client disconnection and process shutdown retain completed snapshots. Disposal can run after finalization or workspace closure using the captured output-root identity; a replaced output directory is rejected. Cancellation or a cleanup error can leave a closed draft with retained snapshots, and the caller can explicitly retry disposal.

Prompt duplication adds another raw prompt estimate. Source framing and repeated exported sections belong to complete-packet `measurement`, which enforces the configured allowance. Filtering a selection reply to codemaps retains its complete component totals.

The token tree marks available codemaps from the current presentation; its selection marker applies to full/sliced source paths. The `content` view supplies source-formatted `File:` blocks with language fences and described slice labels. Full and slice blocks reload the file under its captured raw identity, executable mode and decoding. Slice assembly uses that complete decoded file. Rendered codemaps retain their complete presentation text.

Exact `read_file` requests and explicit source or local-document inputs register authorized ignored regular files in the workspace catalog. Optional codemap selection commits its captured membership before requesting the presentation. A rejected set or cancellation before selection persistence can leave a managed-only record with no selected material. Preview is non-mutating, and `draft_update` admits its complete receipt before committing.

When source or policy changes during extraction, the reply reports `pending_paths` and retains committed membership. Cancellation and unexpected extraction failures propagate to the caller; a later get can acquire a presentation after the captured source and policy are available again.

Native tree and structural exploration use the operation-owned bridge. Closing or cancelling the operation joins admitted rendering before releasing its lease. The tree result contains RPCE-rendered text, root count, note and a continuation bound to captured inventory and request/selection identity. Response caps page complete rendered lines; depth cutoffs and automatic tree reductions are separate from response paging. Selected markers derive from full/sliced source selection; inferred and explicit code-map material are not marked as selected implementation.

A presentation is incomplete while its material bodies are pending.

Mixed roots retain useful targets. A source-coverage diagnostic can coexist with a complete measurement when every delivered material body is settled.

## Finalization and verification

The native snapshot writer requires an output-root capability and writes beneath `_git_data/repos/<repoKey>/<snapshotID>/`. Source snapshot-ID normalization establishes its relative path. The bridge logs that recovery as `gitCurrentSymlinkFailed`. `readGitSnapshotCurrent` reads both pointer forms using the retained RPCE reader. If a symlink's target is missing, the result is absence; an ID stored as text is returned even when the named snapshot is missing. Snapshot-file reads require the same output-root capability, reject symlinks and traversal, and verify the returned bytes against their SHA-256 and byte count. A later pointer failure or cancellation retains completed snapshot files.

Git-snapshot capabilities permit mutable artifact files; final-bundle capabilities permit exclusive fixed-name writes and manifest publication. Each operation accepts its own capability kind. A failed snapshot write retains earlier completed files and reports the native failure and errno. Ordinary failures attempt temporary-file cleanup. Cancellation retires and joins the owned native worker; completed files remain available for diagnosis.

Native maintenance operations limit each workspace to 25 snapshots after publication. To enforce the count, maintenance sorts snapshots by generation time, repository key, then snapshot ID. Rendering uses the captured materials, file tree, automatic Git, preset and constraints with the replacement prompt and the new output name. The allowance is `budgetUnits` when supplied; otherwise it is the captured budget raised to the rendered packet's units, so a prompt-only packet always fits the allowance that verification re-renders against. It reacquires no selection, codemap or Git target and makes no model call. Output over a supplied `budgetUnits`, or a nonempty prompt that the captured preset excludes (`promptExcluded`), returns `blocked` without creating the directory. Finalization and preparation share the manifest builder and manifest-last publication sequence in `bundle-publication.ts`. Revalidation reports the changed source with `sourceChanged`. `refresh`, or nonempty `requiredSources`, `documents`, `patches`, `remove` or `demote`, rebuild instead: the captured request, its canonical selection including omitted sources, the edits and the additions form a new draft request in the saved codemap mode. `remove` and `demote` paths resolve against the saved materials before any rebuild work, where `root/path` names a source and an alias names a Git artifact. Removal drops optional explicit sources from the selection and leaves the named artifacts unadopted. Demotion turns optional full or sliced sources into codemap selections and keeps the codemap mode, as demotion through `manage_selection` does, so automatic codemaps that only the demoted sources referenced drop out. Unknown, repeated, required, automatic or preset-added targets return `invalidSelection` with every problem listed. The draft sets the prompt verbatim and finalizes normally. While saved `gitMap` or `gitPatch` materials remain after removal, `refresh` returns `refreshRequiresDiscovery`, and other rebuilds first pass current verification; each remaining artifact is then reauthorized from its snapshot manifest, checked against its recorded identity, recataloged for the workspace and selected through the draft's Git publication commit path.

## Discovery and client ownership

`MipmuxRuntime.createClient(runner)` creates a client owner for public workspace/draft IDs and a `JobRegistry`. The runner is a transport-neutral capability receiving the caller's purpose, task, constraints, discovery hints and root names, an admitted-state `initialContext`, scoped tools, cancellation and progress. A null runner supports manual operations. Runtime closure closes its clients before the remaining workspace/process owners. Client closure rejects new work, cancels jobs and admitted manual operations, joins settlement, and releases workspace leases. Terminal manual finalization, whether ready, failed or cancelled, and terminal jobs release their draft leases while retaining inspection data; blocked drafts stay editable and leased.

`initialContext` is captured after required and inferred material admission and before scout dispatch. It identifies draft/revision, inventory, mode, fixed constraints, all roots, explicit selections, IDs for inspecting documents and patches, inferred count/item units and complete-packet accounting. Inferred paths are available through the overview and paged inspection. `DiscoveryInput` contains these unrendered facts plus the file tree, current prompt, original task, purpose, hints, adjusted budget and admitted interaction/Git settings. After template admission, one native operation returns the system policy and startup message. Pi receives that startup message followed by the raw observation in `mipmux_runtime`; current-prompt content and task-specific discovery instructions remain separate source sections.

The initial file map tries full, depth-three full, directories, depth-three directories, then selected-only views, with root names when none fits. The tree fit check uses 6000 estimated units before legends and notes. Its sibling cap is 100, raised to the selected-child count. Stars identify explicit full/sliced files; pluses identify delivered codemaps. Skipped inventory entries are omitted; directory, file and acquisition-failed entries remain eligible. Overview omissions affect presentation only; paged exploration supplies detail.

Builder admission requires numeric `budgetUnits` and a client-local request ID. The canonical digest includes the workspace handle and complete request. Duplicate input returns the existing job; conflicting input fails. Draft acquisition registers its freshness barrier and lease before admission returns. The runtime reconciles the workspace and acquires required material before discovery. The job transitions through discovery settlement and the existing draft finalizer; that finalizer owns the publication claim. Cancellation after the claim reports `publicationInProgress` and leaves the claimed operation to finish.

`context_builder_wait` observes one job until its duration elapses, a question becomes available or the job settles. Its cancellation and timeout leave the job running. Progress has monotonically increasing sequence numbers, and callbacks cannot change execution. Terminal snapshots remain retrievable until client closure. A blocked snapshot names an inspectable builder draft; public updates and finalization accept only caller-created manual drafts. MCP replaces a ready snapshot's `bundle.manifest` with a bundle receipt: the directory, `context.md` path and identity, accounting, one entry per delivered material with its estimated units, omissions and the resulting prompt. `draft_finalize` returns the same receipt without the prompt, and `context_prepare` replaces its material list with `added` and `removed` entries relative to the saved bundle. In ready and blocked snapshots, discovery completions appear as a number rather than a list, because a job completes only when each one matches the effective model, together with their summed token `usage` and `toolCalls`, the model's calls counted by tool name. Calls made inside a `codemode` script are not counted. Library and CLI results retain the manifest and complete discovery receipt.

`ContextBuildRequest.clarification` enables form interaction for the owning job. Its optional `questionTimeoutSeconds` defaults to the source value of 300 seconds; the resolved value reaches the native discovery policy and controls which tools the worker admits. Without this request field, `ask_user` is absent from the scout's tools. Enabling requires the MCP request's explicit `elicitation.form` capability. Library callers supply the form capability when starting a job and service `pendingQuestion`/`answerQuestion` on that same client.

`JobRegistry` owns one interaction per job through preparation, pending response and answer conversion. It rejects overlapping questions and uses a random question ID to bind each response to its client and job. A response consumes that pending ID before native answer conversion; replayed, late and cross-job responses fail with `interactionNotCurrent`. The native parser supplies question validation, text/options, schema and answer conversion. The scout receives the source `answers`, `selected_options`, `custom_response`, `skipped`, `timed_out` and elapsed-time fields. Final-selection approval is the source prompt's instruction to invoke `ask_user` before halting.

The question deadline belongs to the job, independently of the wait observer or the form displayed by the client. On timeout, native conversion receives an empty draft and discovery can continue. A client that later submits the expired response receives `interactionNotCurrent`. Cancelling the form fails that tool call; cancelling the job or closing the client aborts the interaction and joins its tools before settlement. Scheduling uses Node's maximum timer delay in segments so the platform limit does not shorten a longer source timeout. Interaction logs contain job/question IDs and state, not question or answer text.

The Pi adapter launches one Node process through `ProcessSupervisor` for each run. Private LF-delimited JSON messages include generation/job identities. Closed schemas validate tool calls, evidence and terminal messages. The parent injects the pinned draft and operation, rejects unknown/retired generations and duplicate calls, and closes admission immediately on cancellation. Child closure alone cannot settle a pending parent tool. A terminal response received with outstanding parent work is rejected.

Worker retirement cancels the job's operation before joining pending parent tools, including its physical native reads and search processes. Shared indexing and other operation owners remain independent. Records received after retirement cannot alter the discovery receipt.

Pi discovery configuration requires an absolute `promptTemplatePath`, an `mcp` reference or `null`, and a `codemode` boolean. The parent opens the template nonblocking, checks the opened descriptor is regular, reads with the run's cancellation signal, and closes the descriptor. Strict UTF-8 decoding precedes native parsing of the versioned named sections and placeholders. `DiscoveryPromptInput` admits wire fields in its initializer and performs semantic parsing/composition in `render()`, producing a correlated `discoveryTemplateRejected` result for an expected syntax diagnostic. Editing the file affects later jobs; a running job retains its admitted bytes and composed strings. The worker receives rendered policy and startup text.

Missing/open/read failures become `discoveryTemplateReadFailed` with the system code; nonregular files become `nonRegularDiscoveryTemplate`; encoding or semantic failures become `invalidDiscoveryTemplate`. Safe diagnostics identify the reason, physical LF line and known section where applicable. Admission failure starts no Pi worker and leaves discovery receipt data null. Cancellation and unexpected native failures retain their existing codes and process-settlement ownership.

A discovery receipt records adapter `mipmux-pi-v2`, `templateVersion: mipmux-discovery-template-v1`, `template: { path, identity }` for the admitted raw bytes, and `policyIdentity` for the exact rendered system policy. Each identity contains SHA-256 and byte count. SDK working-directory framing, tools, startup messages and subsequent conversation are outside that policy digest. Packet integrity/current verification replays archived packet inputs and bytes independently of mutable policy files and discovery receipts.

The worker receives retained system text for its controlled resource loader and constructs in-memory session/settings. Its base tools are the scoped exploration, Git, selection, prompt and draft tools. When `codemode` is true, the model is also offered `codemode`, whose scripts can call those tools but no models, and the rendered policy lists it among the available tools. Before the first model request the session must offer the model exactly these tools and let scripts call exactly the scoped tools, or discovery fails with `unexpectedToolAccess`. It selects one physical model and rejects thinking clamping. The adapter observes the existing shared stream function's result promise for both ordinary and summary calls; it does not consume the stream iterator again or implement recovery. Retry, provider, compaction and transport settings are explicit, and cache warming is off. `retry.provider.timeoutMs` accepts zero, which leaves the Codex HTTP response-header deadline disabled. HTTP idle and WebSocket connection timeouts have separate settings. The parent assembles the receipt from typed preflight, assistant, prompt, completion and lifecycle facts, retaining received evidence after forced worker closure.

`discovery.mcp` is `null` or `{ "agentDirectory": "/absolute/path" }`. The directory must exclude group/other permissions and contain a regular, strict-UTF-8 `mcp.json` file. Each job retains the configuration read at its start; edits apply to subsequent jobs. Only configured HTTP servers and exact selected tools are authorized.

The `mcpServers` object requires at least one server. Server names start with an ASCII letter and contain only ASCII letters, digits and underscores. URLs use HTTPS, or HTTP on `localhost`, `127.0.0.1` or `[::1]`, with no userinfo. Each server requires `exposure: "hidden"` and at least one exact tool name with `"direct"` exposure in `toolExposure`. Optional fields are `headers`, Pi's `oauth` settings, `description`, a positive per-request `timeout` in seconds, and `type: "http"`. Header values and `oauth.clientSecret` accept literal values and native escapes: `$$` for a dollar sign and `$!` for an exclamation mark. Commands and environment-variable interpolation in those fields are rejected. Tool selection authorizes names; server-side read-only credentials or scopes limit the server's privileges.

MCP OAuth state is stored in `mcp-auth.json` and server logging notifications in `mcp.log` under the private directory. CLI/MCP hosts exclude that directory and the declared/physical targets of `mcp.json` and `mcp-auth.json` from source access. Library hosts must include those paths in `credentialPaths`.

Configured discovery can call the selected MCP tools and the exposed mipmux context tools, directly or, when `codemode` is true, from `codemode` scripts. A failed tool-availability check prevents the next model request and fails discovery with `mcpToolsUnavailable`. Interactive sign-in must precede jobs; the worker never opens a login browser. Source access, draft mutation, budget enforcement and publication remain subject to mipmux's workspace and draft contracts.

`DiscoveryReceipt.mcp` is `null` when MCP is disabled. Otherwise it records the admitted file's raw-byte `configSHA256`, authorized server/tool names and hashed endpoint URLs. Readiness `ready` records the first successful availability check, registered tool names in `tools` and a digest of their declarations in `declarationSHA256`; `unavailable` records a failed check. Shutdown `dispatched` means the shutdown event returned with no observed handler failure; `handlerFailed` records an observed handler failure. `notObserved` in either field means no corresponding observation was received.

`workerClosed` establishes local HTTP connection release. Readiness and shutdown observations do not certify remote cancellation, acknowledged session deletion or complete SDK cleanup. Successful discovery requires MCP readiness `ready` and shutdown `dispatched` whenever MCP is configured.

Success requires one accepted prompt, prompt resolution, `agent_settled`, idle completion, a latest normal-stop nonempty text/thinking-only assistant message, joined observations, disposal and child closure. The parent validates these receipt facts and settles its own tools before finalization. The final assistant acknowledgement is diagnostic evidence; the committed prompt and selection remain the artifact authority. Recovered attempts stay recorded even if the SDK omits them from projected conversation state. Independent server identity can be unavailable, and local closure makes no claim about remote cancellation or billing.

Model registration consumes the validated configuration snapshot. Every locked credential read and write checks for executable configuration before key resolution or persistence. OAuth refresh uses Pi's serialized persistent credential storage. The credential adapter requires Pi 1.0.2 and the audited authentication module's exact source and declaration hashes; a mismatch fails with `unsupportedCredentialSDK`.

MCP hosts use the official 2.3.0 `serveStdio` factory and negotiation. Factories register handlers without storage or worker acquisition. The connection owns its client; stdin EOF joins application shutdown independently of transport closure. Shared TypeBox schemas feed `fromJsonSchema` and application validation. Each discovery runner supplies its result encoding to scoped tools for serialized cap measurement. Pi measures JSON text content and error metadata; MCP measures its single text block, the structuredContent that only structure results carry, and error flags. Error projection exposes stable codes, known revision/required-size fields and validated cache recovery targets. Failed or cancelled builder receipts carry the same validated `target`, or `null`, through library results, MCP `context_builder_result`/`context_builder_wait` and CLI `build` output. Cache corruption/conflict targets contain an explicit artifact or reuse kind and a lowercase SHA-256 key. CLI recovery requires `cache invalidate --kind artifact|reuse --key <sha256> --config <absolute-file>`; library recovery uses `runtime.artifacts.invalidate(key)` or `runtime.artifacts.invalidateReuse(key)`. Each invalidation removes only the named record. Read-range errors include the fixed source diagnostic; exception messages and arbitrary details remain private.

`@earendil-works/pi-codemode` is pinned directly to 1.0.2 alongside Pi 1.0.2. Pi imports the `MCP_TYPESCRIPT_PREAMBLE` declaration exported by that version; the installed-package test exercises this import through the actual discovery worker.

Pi pins `undici` to exactly 8.10.2, which has advisories GHSA-4qv8-2p9j-2685, GHSA-f72v-6w45-q472 and GHSA-xjj6-f33q-929c. `package.json` overrides that pin with 8.12.2. The discovery worker loads `undici` through Pi's settings module but sends model requests through Node's built-in `fetch`, because mipmux does not call Pi's `configureHttpDispatcher`. npm applies `overrides` only in the root project, so a project that installs the mipmux package resolves Pi's pinned 8.10.2 unless that project declares the same override.

The embedded dependency identity and terminal receipt use `buildLockSHA256` for the SHA-256 of the package-lock.json consumed by the build. Installed packages may resolve a different transitive graph; its lockfile and audit are separate deployment evidence.

MCP factory and stdio host `closed` promises resolve after successful cleanup or reject after cleanup failure. EOF, server-close and signal shutdown join application and transport cleanup. Cleanup continues after a failure, then the CLI reports a sanitized failure on stderr and exits nonzero; protocol stdout contains only MCP messages.

The stdio host forwards protocol bytes through a host-owned Writable to shared stdout. After application work and any claimed publication finish, shutdown cancels the wrapper's pending writes and joins their rejected send promises before completing transport cleanup. Expected output cancellation is separate from output or cleanup failure. The wrapper closes while shared stdout remains open for its owner. Bytes already accepted by stdout cannot be retracted, and local write settlement does not prove peer receipt.

The compiler uses strict NodeNext application checking with `skipLibCheck: true`. This exempts internals of third-party declaration files: Pi 1.0.2's generated model declarations omit JSON import attributes, and Google GenAI's declarations reference an optional legacy MCP type. Application checking retains `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` and `verbatimModuleSyntax`. Runtime integration tests exercise the actual pinned packages.
